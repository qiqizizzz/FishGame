## 程序集边界

| 程序集 | 覆盖目录 | 依赖 |
| --- | --- | --- |
| `QTower` | `Framework/QTower/`（不含 `Editor/`） | `Utils`、`Unity.Addressables`、`Unity.ResourceManager`、`UniTask`、`UniTask.Addressables` |
| `QTower.Editor` | `Framework/QTower/Editor/` | 仅 `QTower`，`includePlatforms` 限定 Editor |
| `Utils` | `Utils/` | 无，零依赖叶子层 |
| `Assembly-CSharp` | `Game/`、`Module/`、`UI/` | 未建 asmdef，自动引用以上全部程序集 |

## 依赖方向

```text
             Game                业务层：组合根与场景入口
           /      \
        UI        Module         UI 目前为空，Module 现有 Timer
           \      /
              v
      Framework/QTower   <   QTower/Editor
              |                编辑器层只依赖 QTower，不进包体
              v
            Utils                工具层：零依赖
```

- 引用只允许自上而下：业务层 → 框架层 → 工具层
- 禁止 `Framework/QTower`、`Utils` 反向引用 `Game`、`UI`、`Module`
- 新增玩法系统放 `Module`，新增界面放 `UI`，通用能力放 `Framework/QTower`

## 启动链路

```text
GameScene.Awake
  ├─ HierarchyFindTool.FindSceneRoot(UIRoot)
  ├─ DontDestroyOnLoad(GameScene + UIRoot)
  ├─ GameApp.Instance.Init()  ->  new TimeManager / ControllerManager / UIManager
  └─ GameApp.UIManager.SetRoot(uiRoot)

GameScene.Start
  └─ ControllerManager.Register(ControllerType.Game, new GameController())

GameScene.Update
  └─ GameApp.Instance.Tick(deltaTime)
        ├─ TimeManager.Tick
        └─ ControllerManager.Tick  ->  BaseController.Tick

GameScene.OnDestroy
  └─ GameApp.Instance.Destroy
        UIManager -> ControllerManager -> TimeManager -> ResManager
```

# 三、场景设计规范

> 约束来源：`Assets/Scripts/Game/GameScene.cs:17`、`Assets/Scripts/Game/GameScene.cs:31`、`Assets/Scripts/Utils/Find/HierarchyFindTool.cs:19`、`Assets/Scripts/Framework/QTower/MVC/UIManager.cs:128`

## 硬性约束

场景层级不是审美问题，而是被框架代码写死的。以下每一条都有代码依据，违反即功能失效。

| 约束 | 代码依据 | 场景做法 |
| --- | --- | --- |
| `UIRoot` 必须是**场景根节点**，名字逐字符一致 | `FindSceneRoot` 只遍历 `GetRootGameObjects()` | 不能塞进 `Game` 的子层级，不能改名 |
| `GameScene` 挂在常驻根物体上 | `DontDestroyOnLoad(gameObject)` | 整棵 `Game` 子树跨场景常驻 |
| `UIRoot` 常驻，且不挂任何脚本 | `DontDestroyOnLoad(m_uiRoot.gameObject)` + `SetRoot(m_uiRoot)` | 只放 Canvas 相关组件 |
| 界面预制体根节点必须挂 `Canvas` | 只有 `GetComponent<Canvas>() != null` 时才写入 `SortingOrder` | 每个界面一个嵌套 Canvas |
| 只能有一个 `AudioListener` | 常驻相机唯一 | 玩法场景不要再放带 Listener 的相机 |
| 输入模块走旧版 | `Packages/manifest.json` 未装 `com.unity.inputsystem` | `EventSystem` + `StandaloneInputModule` |
| 资源池与音频节点自动创建 | `ResManager` 建 `ResPoolRoot`，`SoundManager` 建 `SoundRoot` | 场景里**不要**手动创建这些节点 |

## 目标层级

```text
Game                    [常驻根] 挂 GameScene
├── Main Camera         Camera + AudioListener
└── EventSystem         EventSystem + StandaloneInputModule

UIRoot                  [常驻根] Canvas + CanvasScaler + GraphicRaycaster
├── HUD                 RectTransform 全屏拉伸（常驻信息层，可选）
├── Panel               RectTransform 全屏拉伸（功能面板层，可选）
└── Popup               RectTransform 全屏拉伸（弹窗结算层，可选）
```

- `Game` 与 `UIRoot` 是**兄弟根节点**，运行后一起进入 `DontDestroyOnLoad` 场景
- 截图里的 `Game` 已经包住相机与平行光，方向正确，只需补 `GameScene` 组件与同级 `UIRoot`

## 组件清单

| 节点 | 组件 | 关键参数 |
| --- | --- | --- |
| `Game` | `GameScene` | 场景唯一入口，不要再挂别的脚本 |
| `Main Camera` | `Camera`、`AudioListener` | Overlay 模式下 Culling Mask 不影响 UI |
| `EventSystem` | `EventSystem`、`StandaloneInputModule` | Input Actions Asset 留空 |
| `UIRoot` | `Canvas` | Render Mode = Screen Space - Overlay |
| `UIRoot` | `CanvasScaler` | Scale With Screen Size，1920x1080，Match = 0.5 |
| `UIRoot` | `GraphicRaycaster` | Blocking Objects = None |
| `HUD` / `Panel` / `Popup` | 仅 `RectTransform` | Anchor 全屏拉伸，四边偏移 0 |

- 给 `Canvas` 挂上后 Unity 会自动补齐 `CanvasScaler` 与 `GraphicRaycaster`，缺了再手动加
- `UIRoot` 上不要加 `CanvasGroup`，会统一影响透明度与射线，干扰单个界面的显隐控制
- 需要 Screen Space - Camera 或后期做 3D 场景遮挡时，再新建 `UI` Layer 并赋给 `UIRoot`

## 界面预制体规范

- 路径：`Assets/Prefabs/UI/UICombatHUD.prefab`，Addressables 地址与 `UIDefines` 常量保持一致
- 根节点命名 = 地址 = 视图类名，`RectTransform` 全屏拉伸、四边偏移 0
- 根节点挂嵌套 `Canvas`，**不要**再挂 `CanvasScaler` 与 `GraphicRaycaster`，缩放与射线统一由 `UIRoot` 承担
- `UIBase` 子类显式挂在预制体根上。`UIManager.Open` 在取不到组件时会 `AddComponent` 兜底，但 Inspector 里手配的引用会全部丢失
- `UIData.Parent` 目前统一填 `GameApp.UIManager.UIRoot`，层级高低靠 `SortingOrder` 表达

| SortingOrder | 用途 |
| --- | --- |
| 0 – 99 | 常驻 HUD |
| 100 – 999 | 功能面板 |
| 1000 – 1999 | 模态弹窗与结算 |
| 9000 以上 | 全局 Loading 与系统级提示 |

## 搭建步骤

1. 打开 `Assets/Scenes/Game.unity`
2. 选中根物体 `Game`，Add Component 搜 `GameScene`
3. Hierarchy 空白处右键 Create Empty，命名 `UIRoot`，**保持根节点层级**
4. `UIRoot` 添加 `Canvas`，Render Mode 选 Screen Space - Overlay，确认 `CanvasScaler` 与 `GraphicRaycaster` 就位
5. 把编辑器自动生成的 `EventSystem` 拖到 `Game` 之下。留在根节点会在切场景时被销毁，表现为 UI 突然点不动
6. 多场景规划下把 `Directional Light` 移出 `Game`，否则常驻光照会与各场景自带灯光叠加；单场景可保持现状
7. Build Settings 加入并勾选 `Game.unity`，移除 `SampleScene`（当前构建列表只有 `SampleScene`）
8. Addressables 新建 `UI` 组，按 `UIDefines` 的地址登记界面预制体
9. 运行验证

## 验收清单

- Console 无 `查找场景根节点失败：场景 Game 中未找到 UIRoot`
- 运行后 `Game` 与 `UIRoot` 都在 `DontDestroyOnLoad` 下
- `GameApp.UIManager.UIRoot` 非空，`ControllerManager` 里存在 `ControllerType.Game`
- UI 按钮可点击，切场景后 HUD 不消失也不重复
- 关闭界面后 `ResPoolRoot` 无残留实例

## 已知风险

- `GameScene.Awake` 找不到 `UIRoot` 时直接 `return`，`GameApp` 完全不初始化，只留下 `HierarchyFindTool` 一条 Error。按项目判空规范，这属于用判空掩盖必要引用缺失，建议改为 `#if UNITY_EDITOR` 下 `Debug.LogError` 主动暴露
- `GameController` 构造函数中的 UI 注册代码目前整段注释，`UICombatHUD` 与 `UISummary` 尚未真正接入
