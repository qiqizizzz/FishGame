# FishGame 档位标记改用字母拼写（消除罗马数字乱码）

> 上一轮：2026-10-11/2-商店卡面收窄与覆盖格对齐网格.md　　本轮日期：2026-10-11　　基线 HEAD：5f87cde「修复字体大小」
>
> 主设计文档：设计文档/05-商店道具重规划与合成规划.md（本轮不动数值与货架，只改显示字形的来源）

## 一、用户诉求原话

> 「罗马字这边你别用完整的数字符号，会导致乱码，推荐用一个一个字母拼出来，你把现在项目里面的罗马文字都改一下，比如 II 改成两个 I」

截图位置：商店详情小窗 `Txt_DetailName`，运行时文本为「教学鱼竿 + 一枚整字罗马数字」，末尾那字符显示成两根跟汉字笔画完全不搭的细竖条。

## 二、根因（探针实测，不是猜的）

工程里两枚 SDF 字体资产都是 `atlasPopulationMode: Dynamic`，缺字会去源 ttf 现取字形；源字体没有的字符就掉进回退字体，字重字高全变，看起来就是「乱码」。

`FontEngine.LoadFontFace(ttf, 90)` + `TryGetGlyphIndex` 逐字符实测：

| 字符 | ZCOOLKuaiLe-Regular.ttf | MaoKenTangYuan-beta0.12.ttf |
| --- | --- | --- |
| I (U+0049) | OK glyph=9 | OK glyph=44 |
| V (U+0056) | OK glyph=22 | OK glyph=57 |
| X (U+0058) | OK glyph=24 | OK glyph=59 |
| U+2160 | NO GLYPH | OK glyph=195 |
| U+2161 | NO GLYPH | OK glyph=196 |
| U+2162 | NO GLYPH | NO GLYPH |
| U+2163 | NO GLYPH | NO GLYPH |
| U+2164 | NO GLYPH | NO GLYPH |

ZCOOL 快乐体（商店面板用的那枚）整个 U+2160 段一个字形都没有，所以靠回退字体勉强出形的那两个也是错的字形，后三个直接没形。毛肯糖圆体反过来只有前两个有、往后同样缺。两枚字体都完整覆盖 ASCII 拉丁字母，因此「用字母一个一个拼」是唯一同时喂饱两枚字体的写法。

顺带一条同源结论：`BackpackItemSO.MAX_TIER = 3`，实际只会用到 I / II / III，数组里 IV 与 V 是留给后续开上限的余量。

## 三、改动落点

全工程扫描（.cs 字符串字面量 + .asset / .prefab / .unity 的 m_text、ItemLabel、Description，YAML 的 \\uXXXX 先反转义再判），整字罗马数字**只有一处**：

- `Assets/Scripts/UI/Shop/UIShopGoodsName.cs:17` 的 `m_tierNumerals`

这一处就是唯一真源。`Of()` 与 `TierMark()` 被 `UIShopPanel.cs`（详情窗名、卖出日志、tooltip 标签）与 `UIShopSlotItem.cs`（背包块与暂存格标签）共 6 个调用点复用，改一个数组，商品卡、背包、暂存架、详情小窗四处同时跟着变，不存在第二处要改。

| 位置 | 旧 | 新 |
| --- | --- | --- |
| `m_tierNumerals` | 五个整字罗马数字 U+2160..U+2164 | `{ "I", "II", "III", "IV", "V" }` |
| 字段上方 | 无说明 | 两行 `//` 注释，写清为什么不用 U+2160 整字 |
| 文件头描述 | 装备带档位罗马数字 | 装备带档位字母标记 |
| 文件头第 8 行 | 挂了个整字罗马数字反而是噪音 | 挂个 I 反而是噪音 |
| `TierMark` 的 summary | 取档位对应的罗马数字 | 取档位对应的字母标记 |

## 四、编译后反射复核（探针 128）

`isCompiling=False`、`isPlaying=False`：

```
TierMark(1) = [I]    codes=0049
TierMark(2) = [II]   codes=0049,0049
TierMark(3) = [III]  codes=0049,0049,0049
TierMark(4) = [IV]   codes=0049,0056
TierMark(5) = [V]    codes=0056
TierMark(6) = [6]    codes=0036        // 越界退回阿拉伯数字，行为未变
```

## 五、顺手做的一次全量字形体检（探针 127）

把全部运行时可见文本去重后共 **749 个非 ASCII 字符**，逐个字形查两枚源字体：

| 字体 | 缺字 | 说明 |
| --- | --- | --- |
| ZCOOLKuaiLe-Regular | 1 个：U+2605 星号 | 唯一用到它的是 `UIResultPanel.prefab` 里那枚星，而该节点的 `m_fontAsset` 是**毛肯糖圆**，毛肯有这枚字形，所以实际不会缺形 |
| MaoKenTangYuan-beta0.12 | 1 个：U+00B7 间隔号 | 只出现在 `Assets/Editor/BackpackConfigSOEditor.cs`，编辑器工具窗口的排版点，不上游戏画面 |

结论：改完这一处之后，游戏画面上**没有任何字符会再掉回退字体**。之前那批鱼名缺字已经换成谐音字，这次一并复核过，没有回潮。

## 六、没碰的东西

- 两枚字体资产一个字形都没往里烘焙。V 不在 ZCOOL 的 `characterTable` 里（当前只烤了 83 字），但 Dynamic 模式会在需要时现取现用，运行期不会缺形，只是第一次画到该字时多一次 rasterize
- `设计文档/AI归档记录/2026-10-9`、`2026-10-10` 里的归档文档仍写着当年的整字罗马数字 —— 那是历史记录，改写等于篡改档案，留着
- 商店货架尺寸、价钱图标、覆盖格对齐（上一轮的三条）本轮一行没动
- `Bg/Panel_Shop/Title` 与 `Assets/Font/ZCOOLKuaiLe-Regular SDF.asset` 的未提交改动都是用户自己的，未回退
