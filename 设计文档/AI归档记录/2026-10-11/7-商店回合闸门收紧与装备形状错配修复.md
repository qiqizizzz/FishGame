## 二、问题A：回合稀有度闸门

### 2.1 根因链

`ShopService` 建权重表时不带回合上限，任何回合都能抽到最高档。第一版闸门已把**常开格**收紧为「第 N 回合最高只出第 N 档」，但**付费格**沿用「整条线提前一回合」，于是 R2 的付费格 cap = round+1 = 3，仍会上架 III 级装备与珍罕布。用户明确反对「第二回合出三级」，故本轮把**最高档从「可提前」里摘出来**。

### 2.2 新闸门曲线

| 回合 | 常开格装备档 | 付费格装备档 | 常开格布稀有度下标 | 付费格布稀有度下标 |
| --- | --- | --- | --- | --- |
| R1 | ≤ I | ≤ II | ≤ 1 | ≤ 2 |
| R2 | ≤ I~II | ≤ **II**（原 III） | ≤ 2 | ≤ **2**（原 3） |
| R3+ | ≤ III | ≤ III | ≤ 3 | ≤ 3 |

规则一句话：**付费格提前一回合开闸，但最高档两路同回合**——花钱买的是「更早见到好东西」，不是「提前把顶级东西搬进场」。

### 2.3 实现

`ShopService.cs` 四个闸门方法改为共用两条参数化实现，`advance` 表示这条线比回合数提前几档：

- `freeTierCap() / paidTierCap()` → `tierCap(0) / tierCap(1)`
- `freeRarityCap() / paidRarityCap()` → `rarityCap(0) / rarityCap(1)`
- `tierCap(advance)`：`clamp(m_round + advance, FIRST_TIER, TIER_COUNT)`，若已顶到最高档而回合还没数满（`m_round < top`），退一档到 `top - 1`；退化下界受 `GUARANTEE_MIN_TIER` 保护，避免把花钱开的格子闸成空货架
- `rarityCap(advance)`：同构，新增常量 `FIRST_RARITY = 0`（布料稀有度下标从 0 起算，装备档位从 1 起算，两套口径不能混用同一个下限常量）
- 越闸档位与稀有度**根本不进权重表**（`buildTables / buildClothTables / buildGuaranteeTables` 三处过滤），比抽完再弃掷省得整面货架白重抽

回合号来源：`FishingController.cs:560` → `m_shop.ResetForNewRound(m_run.Round)`，位置在 `m_run.AdvanceRound()` 之后，`RunState.FIRST_ROUND = 1` 为 1-based，R2 传入 2，口径一致。

## 三、问题B：装备 sprite 与占格形状错配

### 3.1 代码依据（为什么圆图标进 1×3 一定难看）

`Assets/Scripts/UI/Shop/UIShopIconFit.cs`：

- `MIN_ANISOTROPY = 1.6f`——素材自身长短轴能量比不到 1.6 就判定「无朝向可言」，不做旋转对齐
- `SQUARE_TOLERANCE = 1.02f`——包围盒长短边差不到 1.02 才当方盒

于是紧凑素材进 1×3（盒比 3:1）时：不旋转 → 缩放被短边卡死 → 画面只占三格中的一格宽，居中一小坨。**这是数据问题，不是算法问题**，算法在这种情况下已经是最优解，必须从形状配置侧改。

### 3.2 度量口径（与算法完全同源）

对每个 sprite 的 `rect` 内 alpha ≥ 26 的像素做 alpha 加权 PCA，取 `sqrt(λ_major/λ_minor)` 作为 aniso——这正是 `UIShopIconFit.solve()` 内部用的同一个量，因此审计结论与屏幕表现一致。另记不透明像素外接框 bbox 与填充率 fill 作旁证。

## 五、注意事项

- **`TierPrices` 序列化形态变化不是数据损坏**：本轮改形状后 Unity 重存这 6 个 `.asset`，把 `List<int>` 的 `TierPrices` 从 dash 列表改写成了打包 hex（如 `3c0000008c00000040010000`）。已逐一运行时复核：swivel 60/140/320、sink 65/150/360、old_customer 80/190/440、glow 100/230/540、stream 70/160/360、wide_gape 95/220/500，`TierPriceCount` 均为 3，与改前完全一致。diff 里看到 hex 串不必回滚
- 改 `.asset` 期间 `OnValidate` 已不含 `AssetDatabase` 调用（早期「改 SO 就卡死进程」的根因已修），可安全走 `SerializedObject.ApplyModifiedPropertiesWithoutUndo` + `SetDirty` + `SaveAssets`
- `Assets/Font/ZCOOLKuaiLe-Regular SDF.asset` 也在未提交列表里，那是 TMP 动态字体图集自动增长，非人为改动
- 闸门只看回合数，不看钱数。若后续想让玩家「花钱立刻解锁顶级货架」，应改 `tierCap(advance)` 的 advance 来源，而不是放开最高档那条退化分支
