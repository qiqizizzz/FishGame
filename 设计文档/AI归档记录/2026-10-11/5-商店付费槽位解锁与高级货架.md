## 一、用户诉求原话

> 「商店这边我建议初始解锁5个槽位，其他5个用一个锁的图标代替，但是下面可以用金币图标+金币数字 用于购买槽位，槽位价钱是用于产出更高级的东西的（比普通槽位概率更高吧应该），这个你可以先列一个表给我，先别写代码」

方案表（06 文档）给出后，五个待拍板问题在同一条消息里全部答完，并授权开工：

> 「1.按顺序解锁，没解锁之前的没法解锁后面的，2,立刻先抽3.要的4.你看情况来5.你画吧，开始写吧」

> 沟通事故记录：五条答案其实早已给全，我却复述问题二次追问，挨了「我刚刚不是回答了吗」。教训：同一条消息里「答案 + 开始写吧」连着出现时，答案就是定稿，不许再问。

## 二、五问五答定稿

| # | 问题 | 拍板 | 落地 |
| --- | --- | --- | --- |
| 1 | 按顺序解锁还是任意顺序 | **按顺序**，前一格没开后面不响应 | `TryUnlockSlot` 只认下一把锁；未轮到的格子只画锁、不标价、不可点 |
| 2 | 解锁后立刻现抽还是等下回合 | **立刻现抽上架** | 扣钱成功当场 `tryAppendEntry(true)`，那一格立刻有货 |
| 3 | 付费格要不要保底 | **要** | `PaidSlotGuarantee = true`，抽不够就强制补一件二级以上装备或稀有以上的布 |
| 4 | 50/80/110/150/200 量级 | **你看情况来**（由 AI 定） | 按方案表原量级写入 SO，总额 590 |
| 5 | 锁图标谁出 | **你画吧** | 脚本生成 `Assets/Art/UI/HUD/Img_Lock.png` 像素锁 |

## 三、代码改动

### Assets/Scripts/Module/Shop/Data/ShopConfigSO.cs（201 行）

新增字段（默认值即定稿值）：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `FreeSlotCount` | 5 | `Range(1,12)`，开局白送的常开格数 |
| `PaidSlotUnlockPriceList` | {50,80,110,150,200} | 一项一个付费格、一档一个价，越靠后越贵 |
| `PaidSlotGuarantee` | true | 付费格保底开关 |
| `PaidItemCategoryWeight / PaidClothCategoryWeight / PaidBlankClothCategoryWeight` | 55 / 40 / 5 | 付费格类别权重：带BUFF布抬高、空白布压低 |
| `PaidTierWeightList` | {30,45,25} | 付费格装备档位权重（常开格是 {70,25,5}） |
| `PaidClothRarityWeightList` | {25,35,28,12} | 付费格布稀有度权重，项数越界钳最后一项 |

新增访问器：`FreeSlots` / `PaidSlots` / `PaidGuaranteeEnabled` / `PaidItemWeight` / `PaidClothWeight` / `PaidBlankClothWeight`，带越界钳位的取数口 `PaidUnlockPriceAt(i)` / `PaidTierWeightAt(tier)` / `PaidClothRarityWeightAt(rarity)`。

`OnValidate` 加断言 `FreeSlotCount + PaidSlotUnlockPriceList.Count == GoodsSlotCount`（现 5+5=10），**只打日志不回写字段** —— 不回写正是为了避开上一轮「改一下 SO 进程卡死」那类 OnValidate 回写再序列化回路。

### Assets/Scripts/Module/Shop/Model/ShopStockEntry.cs

加 `bool IsPremium`（构造参数默认 false），只记「这件是花钱开的格子里抽出来的」，界面拿它染卡底，玩法一条不改。

### Assets/Scripts/Module/Shop/Service/ShopService.cs

- 新增六张付费表：`m_premiumCategoryTable` / `m_premiumTierTable` / `m_premiumBuffClothTable` / `m_premiumBlankClothTable`，外加两张保底专用表 `m_guaranteeTierTable` / `m_guaranteeClothTable`（只装够格的：二级以上装备、稀有以上布）
- `m_unlockedPaidCount` 计数；新属性 `FreeSlotCount` / `PaidSlotTotal` / `UnlockedPaidCount` / `NextUnlockPrice`（全开完返回 0）；`Stock` 语义变为「常开格 + 已解锁付费格」，长度随解锁往上涨
- `RollStock`()：常开格逐格 `tryAppendEntry(false)`，已解锁付费格逐格 `tryAppendEntry(true)`；未解锁格不参与 roll、不进 `m_takenKeys` 去重名额
- 新增 `TryUnlockSlot(RunState)`（175 行）：价为 0 或钱不够返回 false；成功则计数 +1 并当场现抽一件上架（答 2）
- `tryAppendEntry(bool premium)`（384 行）按 premium 分流两套权重；付费格保底链路 `qualifiesAsPremium`（420）/ `appendGuaranteeEntry`（430）/ `forcePremiumEntry`（445），常量 `GUARANTEE_MIN_TIER = 2`、`GUARANTEE_MIN_RARITY = 2`（答 3）
- `ResetForNewRound` 只复位刷新价 + 整面重抽，**解锁数跨回合保留**；只有重开一局 new 新实例才清零

### Assets/Scripts/UI/Shop/UIShopQuality.cs

加两枚现成色：`PremiumTint = Color.Lerp(Purple #8B5CF6, white, 0.5)`（淡紫，米黄底上不撞黄）、`LockedTint = #B8AA94`（灰褐，比商店底暗一档）。

### Assets/Scripts/UI/Shop/UIShopGoodsItem.cs

- `CardMode` 三态：`Goods`（在卖）/ `LockNext`（下一把锁）/ `LockSealed`（还没轮到的锁）
- 新增节点路径常量：`Node_Lock`、`Node_Lock/Node_UnlockPrice`、`Node_Lock/Node_UnlockPrice/Txt_UnlockPrice`
- `SetupLock(price, affordable, host)`（170 行）：灰褐底 + 锁 + 金币图 + 解锁价，可点，钱不够价染 `PriceUnaffordable` 红
- `SetupLocked(host)`（192 行）：只有锁、不标价、`Button.interactable = false`（答 1 的界面表达）
- `enterGoodsMode`（263 行）按 `entry.IsPremium` 决定卡底 `PremiumTint` 还是原色（只染根 Image 自身 sprite，不压暗子节点）
- `handleClicked`（339 行）：非商品卡且是 `LockNext` 时转 `m_host.TryUnlockSlot()`；锁卡不弹详情；`OnBeginDrag` 里 `m_entry == null` 直接 return，锁卡不可拖

### Assets/Scripts/UI/Shop/IShopBackpackHost.cs

接口加 `bool TryUnlockSlot();`（203 行），扣钱开格统一由宿主面板执行，卡片只发意图。

### Assets/Scripts/UI/Shop/UIShopPanel.cs（2099 行）

- 实现 `TryUnlockSlot()`（803 行）：转 `ShopService.TryUnlockSlot`；全开完 → 「付费货架已经全部开完了」；钱不够 → 「解锁这一格货架要 N 金币，钱不够」（与刷新那条同一口径）；成功 → `clearDetail + refreshCounters + rebuildGoods`，并记「已解锁第 X 格货架，花了 N 金币」
- `rebuildGoods`（2006 行）改为**按格铺卡**：`totalSlots = FreeSlotCount + PaidSlotTotal`，逐格三选一 —— 有库存条目上商品卡 / `slot == stock.Count` 上是标价的下把锁 / 其后是不响应的锁。不再用 `m_goodsShown` 计数，否则表达不出「第六格是锁、第七格也是锁」这种顺序关系
- 卡片只开关不销毁（`goodsCardAt`，2044 行）：销毁会延到帧尾被布局算进内容高度
- 边界：奖池抽干导致库存变短时，带价锁跟着 `stock.Count` 往后挪，不会多出一张幽灵锁
- 点面板外关闭不受影响：`isClickHandledBy`（1810 行）沿父链找 `IPointerClickHandler`，锁卡根节点挂着 `Button`，点锁不会被误判成点空白
