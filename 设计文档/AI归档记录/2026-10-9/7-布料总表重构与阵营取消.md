## 二、已落地内容

### 2.1 数据层：一张总表装下布料这条链路

```text
Module/Backpack/Data/ClothCatalogSO.cs   总表本体：稀有度档数组 + 布料数组，Resolve(布,异形) 拼板块
Module/Backpack/Data/ClothRarityTier.cs  一档稀有度：档名 + 抽中权重 + 价格系数，两个数同一行
Module/Backpack/Data/ClothEntry.cs       一块布一行：Id / 布名 / 底色 / 稀有度下标 / 单格基准价 / BUFF 数组 / 异形数组
Module/Backpack/Data/ClothBuffEntry.cs   布上的一条 BUFF：能力线 + 每格额度 + 本布封顶（引用类型，靠实例身份归组）
Module/Backpack/Data/ClothPieceDef.cs    「布 × 异形」拼出来的可上架板块，不占资产，按同一对下标返回同一实例
Assets/Data/Backpack/ClothCatalog.asset  4 档 + 15 块布，8190 B
```

三条关键设计

```text
1 空白布不再单独建资产，它就是 BuffList 留空的那一行，商店按 IsBlank 分进空白池
2 价钱不写死在形状上：单格基准价 × 占格数 × 稀有度系数 × ±10% 浮动，现算，改形状尺寸不用重定价
3 布 × 异形的实例必须稳定 —— BUFF 的封顶归属认的是 ClothBuffEntry 的引用，
  同一个组合每次给新对象就归不了组，所以总表里按 key 缓存
校验全集中在 OnValidate：空行 / 缺 Id / Id 撞车 / 无形状 / 稀有度越界 / 空白布带数值 / 封顶填 0，当场报
```

### 2.2 阵营取消（用户口径：「根本不存在什么阵营」）

```text
一块布 = 一个颜色，颜色只是让玩家认出这块布在堆哪几条线
  → 不落独立资产、不参与聚合、不参与定价，同色出现在多块布上纯属视觉归组
布的封顶与装备的线封顶两条链路互不相干，各自夹各自的
BackpackItemSO 上遗留的 FactionAsset / Page 字段已剪掉并重序列化（14 件装备的历史引用一并清理）
BuffPageSO / BuffFactionSO / BackpackPlateSO 的 CreateAssetMenu 已撤，头注释标「已被 ClothCatalogSO 取代」
PlateLibraryBuilder 的菜单行已注释，防止手抖把 58 个废弃资产生回来
```

### 2.3 自定义 Inspector：`Assets/Editor/ClothCatalogSOEditor.cs`（707 行）

用户嫌默认嵌套数组丑，这里改成「一行一布」的表格：顶部是稀有度档表，下面每块布一行
（色块 + 名字 + 档 + 单格价 + 现算的板块价区间 + 「占带 BUFF 池 x.x%」），展开就地编辑
BUFF 条目和异形列表，异形按位图涂出格子小样，一眼看出这块布长什么样。

本轮实测中还抓出并修掉两个「用户点一下按钮就会踩」的隐患：

```text
隐患 A  点「新增一块布」会白捡上一块布的数据
        SerializedProperty.InsertArrayElementAtIndex 是复制邻元素、不是插空元素，
        在末尾插入等于复制最后一块布（韧网布：3 条 BUFF + 2 种异形），旧代码只覆盖名字
        → fillClothRow 现在给新布清空 BUFF 与异形，并写默认档/默认米白/默认格价 14
隐患 B  增删稀有度档会让全体布料的 RarityTierIndex 静默错位
        ClothEntry 用数组下标引用档位，在 index2 插一档后原本指向 rare/epic 的布全部改指新空白档，
        价钱和抽中权重一起错，且毫无报错
        → remapClothTiers 在增删前抓 TierId 快照、增删后按 TierId 把每块布对回原档，
          被删档上的孤儿布夹到相邻存活档，结果用一行 HelpBox 提示（只显示一趟，不常驻）
        → 顺序必须是 idsBefore → Insert → fillRarityRow → remap，fill 在 remap 前否则新档 id 重复
其他    applyPendingOps 去掉 Undo.RecordObject，撤销交给末尾 ApplyModifiedProperties，一次点击回一步
```

### 2.4 商店侧（口径沿用上一轮，本轮只换数据源）

```text
ShopConfigSO.ClothCatalog 是布料侧唯一入口，板块不再有各自的清单资产
三类权重 装备 55 / 带 BUFF 布 35 / 空白布 10；布内按稀有度抽中权重加权
抽中某块布后，在它的可刷异形数组里等概率挑一个，异形本身不参与稀有度
布料价 = RoundToInt(单格基准价 × 占格数 × 稀有度系数) × (1 ± 0.1)，下限 1
```

## 八、工具坑（累积）

```text
SerializedObject 没有 isDirty，脏检查用 EditorUtility.IsDirty(asset)
InsertArrayElementAtIndex 是「复制邻元素」不是「插空元素」，插入后必须自己覆盖默认值
script_execute 每轮都新编译一个 Roslyn 程序集：static 字段跨调用不保留，`x is 上一轮的类` 恒 false，
  跨调用传数据只能靠 SessionState / 资产 / 磁盘文件；EditorWindow 只能靠 titleContent.text 匹配来关
EditorWindow.update 在 Unity 2022 不可见（CS1061），推帧用 EditorApplication.update += CallbackFunction
  （写成 System.Action 会 CS0029）；推帧器要写成自摘除，否则下一轮拿不到委托、留下常驻空转
GUI 函数只能在 OnGUI 里调，GUI.BeginGroup 直接在 Main 里调抛「You can only call GUI functions from inside OnGUI」
$"{cond ? a : b}" 编译不过（CS8361），要写成 $"{(cond ? a : b)}"；静态类里要写全 ScriptableObject.CreateInstance
改完 .cs 不 assets_refresh 就 script_execute = 在旧程序集上测新代码（本轮踩过，白跑一轮）
长结果写 Temp/*.txt 再读盘，别刷 Console —— Debug.Log 的 stack trace 会把结果淹掉
PowerShell 里 New-Item 没有 -LiteralPath（只有 -Path），Move-Item 有；挪资产要连 .meta 一起挪才保 GUID
assets_refresh(ForceSynchronousImport) 对「整目录挪动 + 一个 .cs 改动」耗时 13.6 s，零报错
console_get_logs 的 logTypeFilter 传 null 会被参数校验拒，省略该参数即 All
脚本调用统一用类名 Script + 静态 Main，className 缺省就是它
```
