### 3.1 幽灵布格（UIShopPlateView）

- 常量：RIM_THICKNESS = 4f（亮面相对暗边内缩 4px）、RIM_DARKEN = 0.28f（暗边 = Color.Lerp(布色, black, 0.28)）
- 节点名常量：CLOTH_NAME = "Img_ClothCell"（暗边整格）、CLOTH_FACE_NAME = "Img_ClothFace"（内缩亮面）
- 两个节点都用 UIShopSlotItem.EmptyCellSprite（即格子底板同一张 sprite），保证幽灵格和真实格子轮廓完全一致
- 只在「手里拖着这块布」时 SetActive(true)，其余时候整批收掉 —— 由 applyClothCellsVisible() 统一决定
- OnBeginDrag：m_isDragging = true → 记录 m_clothLayerIndex → 把 Layer_Cloths 整层 SetAsLastSibling、布自身 SetAsLastSibling（要压过装备层和选中外框层）→ applyClothCellsVisible() → host.BeginPlateDrag()
- OnDrag：m_rect.anchoredPosition = pointerInGrid(eventData) - m_grabOffset，纯跟手
- OnEndDrag：按 SNAP_EPSILON 判断是否真挪过，行主序四舍五入回锚点格 → endDrag() → host.TryMovePlate()
- endDrag() 顺序不能颠倒：先 m_isDragging = false + applyClothCellsVisible()，再还原 m_parentRect.SetSiblingIndex(m_clothLayerIndex)，最后 host.EndPlateDrag()
- OnDisable() 里补一次 endDrag()：面板被关掉、物体被隐藏时走不到 OnEndDrag，不补就会把幽灵格和空地板永久留在场上
- 重铺（Relayout）也可能发生在拖拽中途，所以重铺末尾也调一次 applyClothCellsVisible()，按「现在在不在手上」决定亮不亮

### 3.2 详情区（UIShopPanel）

- 常量：DETAIL_PANEL_NAME = "Panel_Detail"、DETAIL_NAME_TEXT_NAME = "Txt_DetailName"、DETAIL_DESC_TEXT_NAME = "Txt_DetailDesc"
- 字段：m_backgroundRect / m_detailRect / m_detailNameText / m_detailDescText / m_detailTarget / m_detailBuffs（List，复用避免 GC）

- 拖布期间（BeginPlateDrag）收起操作条，EndPlateDrag 后 refreshActionBar() 复原

### 3.3 ★ 本会话新修的真实缺陷：OnInit 判空顺序

- 现象：每次初始化必报一条假错「[UIShopPanel] 背景节点没找到，详情区无处可挂」
- 根因：m_backgroundRect = m_itemsRect.transform.parent.parent as RectTransform 这行赋值写在了 #if UNITY_EDITOR 判空**之后**，判空时它还是 null
- 修法：赋值移到判空之前。现文件 187-188 行为赋值，199-200 行为判空报错块
- 取证：Console 里该条 Error 只出现在 17:14:41（修复前的 __Shot33b 轮次），17:17 / 17:18 / 17:19 / 17:21 四轮均无 → 修复确认生效

## 五、★ 编辑模式拍 ScreenSpaceOverlay UI 的唯一正确配方（下轮直接抄，别再走弯路）

前置：script_execute 里必须传 className；parameters 传不进，改用文件传参 / 结果写 Temp 再读。

1. **先读 center = canvas.transform.position**，必须在改 renderMode 之前读（Overlay 时是 (540,960)）
2. 建 RenderTexture(1080, 1920, 24, ARGB32) + 临时相机：orthographic=true、orthographicSize=960f、aspect=1080f/1920f、nearClip=0.01f、farClip=500f、clearFlags=SolidColor
3. 相机 position = (center.x, center.y, 0f)，rotation = identity
4. canvas.renderMode = ScreenSpaceCamera；**canvas.worldCamera = cam（漏这一行 → 整帧全空，本会话白跑一轮）**；planeDistance = 100f；scaleFactor = 1f
5. Canvas.ForceUpdateCanvases() → cam.targetTexture = rt → cam.Render() → RenderTexture.active = rt → tex.ReadPixels(new Rect(0,0,1080,1920),0,0) → tex.Apply() → File.WriteAllBytes(path, tex.EncodeToPNG())
6. **★ 不做任何翻转**：identity 就是正的（标题在上、文字正常）。之前那份「行翻转」脚本（__Shot33d）会拍出**左右镜像**的图，别再用
7. 收尾必须还原 renderMode / worldCamera / planeDistance / scaleFactor，并 SetActive(true) 被临时藏起来的根节点

标定结论（4 变体脚本 __Shot33e 已证）：identity = 正确；flipV = 左右镜像；rot180 = 上下颠倒。正式 5 张由 __Shot33f 产出。

模拟拖拽：new PointerEventData(EventSystem.current) 后**只赋 position**。屏幕坐标 = canvas 世界 xy（Overlay + scaleFactor 1）。
编译坑：pressEventCamera 是只读的、eligibleTargets 不存在、Vector3 + Vector2 会 CS0034（先赋给 Vector2 局部变量）。
拖拽探针**必须补 OnEndDrag**，否则 m_isDragging 卡真、Layer_Cloths 停在最后的兄弟位。

另一处环境坑（本会话新撞）：script_execute 动态编译里 UnityEngine.SceneManagement.SceneManager **没有** OpenScene，OpenSceneMode 也找不到（GetActiveScene 却可用）。改用 UnityEditor.SceneManagement.EditorSceneManager.OpenScene(path, OpenSceneMode.Single)。

## 六、两个「看着像 bug 其实不是」的结论（别去改）

1. **4_item_detail.png 里教学鱼竿跑到暂存架了**：这是 BackpackModel.TryMovePlate 的既有设计 —— 布被挪走，压在上面的装备失去底子 → 进 orphans → 面板把它塞进暂存架（见 BackpackModel.cs:14 / 273-301 / 515-532）。不是本轮引入的。

另有一条**已排除的误判**：5_after_drop.png 里目视数到 6 个布色块（应为 5），怀疑渲染串位。改用像素采样复核 —— 格心公式 x = 205 + 134 * col、y = 465 + 134 * row，布色 = B4AF90、空底 = CAAA7E，结果只有 (3,0)(3,1)(4,1)(4,2)(4,3) 五格是布色，**恰好 2 格布 + 3 格布**。多出来的错觉是操作条压在 col4 r0 的空白格上。而 refreshActionBar（UIShopPanel.cs:793-847）的规则是 minRow > 0 时条浮在布上方，落下后 minRow=1 → 条在上方，**符合设计**。
