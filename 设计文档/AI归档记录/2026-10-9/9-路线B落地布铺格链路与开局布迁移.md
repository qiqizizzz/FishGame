## 三、我替用户补的一条规则（用户没逐条回答，按最小解释补齐，可推翻）

```text
挪布 / 转布 / 拆布 让某件装备失去底子  →  那件装备自动退回暂存架
暂存架接不住（余量不够）              →  整次操作拒绝，网格与架子一字不变

分工：BackpackModel 只负责「预演 + 挑出悬空件」（CollectFloatingItems / maxOrphans）
      「接不住就整体不动」由 RunBackpack 拿 StashRemaining 决定

理由：开局布也能拆，就一定有人把自家地板整个抽走。与其加锁禁止，
      不如让它退到暂存架 —— 玩家还能从架里把布取回来重铺，
      这正好是用户那句「暂存架本来就是用来给玩家调整格子和 buff 的」的字面意思
```

## 四、代码落地清单（对应 8-*.md §7.5 的 a/b/c/d）

### 4.1 a 数据层 —— `Assets/Scripts/Module/Backpack/Model/BackpackModel.cs`

```text
两层掩码   m_plateMask（格子的唯一来源）+ m_occupiedMask（只装装备）
           UnlockMask 降级成算出来的属性，直接等于 PlateMask，base 那一层彻底不存在
板块 API   CanPlacePlate / TryPlacePlate / TryMovePlate / TryRotatePlate / TryRemovePlate
           板块之间只查 plateMask 互斥，装备压在板块上不算是冲突
装备 API   CanPlace / TryPlace / TryMove / TryRotate 一律要求目标格有板块打底
命中查询   FindItemAt(col,row) 与 FindPlateAt(col,row) 各查一层，同一格允许两层共存
悬空复查   CollectFloatingItems(掩码, 结果表)；任何板块变更后 occupied ⊆ plate 由模型保证
ClearAll / ClearItems / Remove 保持原语义，板块另立一份列表不再混在 Items 里
```

### 4.4 d 商店层 —— `RunBackpack.cs` + `ShopService.cs`

```text
TryAddItem(definition, tier) 按 definition.Kind 分流：
  Kind == Cloth → tryFindPlateAnchor（只看会不会压到别的布）→ TryPlacePlate
  其他          → tryFindAnchor（格得有布底且没被别的装备压着）→ TryPlace
两条都塞不下才 pushToStash；架子也满才算这次拿不下
TryRecallFromStash 同样按 Kind 分流，架上的布能取回重铺
TryRemovePlateToStash(布进架，布自己也占一格，所以留给悬空装备的只剩 StashRemaining-1)
TryRemovePlate(直接丢弃，出售走这条，不进架)
ShopService.cs:134 那一行没动 —— 分流发生在 TryAddItem 内部，商店买布自动就通了
```

## 七、自检工具修掉的 bug：**负向 BUFF 曾被判成填反**（别再改回去）

```text
旧规则   每档 value 必须严格大于上一档
        → bite_glove  -0.05/-0.1/-0.18   被判失败（其实 -0.18 最强）
        → quick_cutter -0.2/-0.4/-0.7    被判失败（同上）
新规则   强弱方向由首档符号定向：正向要求递增，负向要求递减
        → 上面两件改为通过；报告里还会写明是「格数没有一档比一档大」还是「加成没有一档比一档强」
修正后装备库失败项从 6 条收敛到 4 条，且这 4 条全是**数据本身**的问题：

  hold_hatch    · 活水舱    · MaxCarryCount · 格数 3/4/6 · 数值 1/1/2    → 加成没有一档比一档强
  old_customer  · 老主顾    · CoinBonus     · 格数 2/3/3 · 数值 0.05/0.1/0.18 → 格数没有一档比一档大
  stream_hook   · 流线钩身  · LateralSpeed  · 格数 2/3/3 · 数值 0.6/1.2/2    → 同上
  wide_gape     · 宽钩门    · HookRadius    · 格数 2/2/3 · 数值 0.03/0.06/0.1 → 同上

用户口径：「就是数值需要到时候看看调整」→ 本轮只报不改
```
