## 七、路线 B 定稿：布料板块 = 给背包铺出新格子的底板

### 7.1 语义（用户第二轮澄清后定稿：两层，不是三层）

用户原话：「布是放在这些透明格子增加格数的，**一开始的那个五格其实是由 3 格布和 2 格布拼接起来的**」
→ 推翻上一版提的「m_baseMask 开局底板 | m_plateMask」三层方案。**不存在任何底板层，格子只由布提供**。

```text
格子唯一来源   plateMask = 所有已入包布料板块位图的并集（开局那两块布也算在内）
装备层         occupiedMask 只统计装备，且必须 ⊆ plateMask
正交           同一格允许「底下是布、上面压装备」
板块约束       布料板块之间不得重叠（互查 plateMask）；装备必须落在 plateMask 覆盖的格内
开局即两块布   不再画开局掩码，改成配置里预放两块布：
                 cloth_blank x line_3   锚点 (col2,row0)  -> 位 {2,10,18}
                 cloth_blank x domino_2 锚点 (col3,row0)  -> 位 {3,11}
               并集 = {2,3,10,11,18} = 0x00040C0C，与用户手画的 UnlockMaskList[0] 逐位相同
               （位序见 ShapeMask：bit = 行 x ROW_STRIDE(8) + 列；domino_2=0x101、line_3=0x10101 均为竖向）
退役           UnlockMaskList / ExpansionCostList / UnlockStageCount / UnlockMaskAt / ExpansionCostAt 全删；
               BackpackConfigSOEditor 那排「清空本级 / 填满本级 / 加一级 / 删末级」工具条整排退役
```

### 7.1b 由这个模型自动掉出来的规则（不需要新代码路径）

```text
拆布 / 挪布会让压在上面的装备悬空  ->  直接拒绝，提示「先把装备挪开」
                                    ->  复用 TrySetUnlockMask 里那条「新掩码必须盖住全部已放物品」的校验
布可以移动可以旋转                  ->  这正是用户说的「通过旋转、位移让格子得到充分利用」
```

### 7.3 为什么必须走 B（硬证据）

用户手改的 `Assets/Data/Config/BackpackConfig.asset` 开局只解锁 **5 格**（`0x00040C0C`），
而占 6 格的 `slab_6` 异形布今天**根本放不进背包** → 「买布 = 买格子」这条路当前不通。
现在布和装备抢同一批格子，越买布越挤，与用户的设计正好相反。

### 7.4 BUFF 生效时机

用户早已定：「板块的 BUFF 是放进背包就一直生效」= **常驻生效（方案 ①）**。
归档三 §八 推荐过的「覆盖生效 ②」只能作为后续可选项提一句，**不许擅自替换**。
有下游消费方的四条线：`ReelSpeed / MaxCarryCount / LineLength / LurePull`；
零消费方（先存着别接）：`TensionMax / TensionRelief / DetectRadius / CoinBonus`。
