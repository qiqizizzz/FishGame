### 3.1 单击只选中，旋转交条上（UIShopItemView / UIShopPanel）

- `OnPointerClick`：先判 `m_wasDragged`（拖完紧跟一次点击，不能当选中），再 `m_host.SelectItem(m_item)`，**不再有 TryRotate**
- `SelectItem`：同一件再点一次 = 取消；选中装备时把 `m_selectedPlate` 清空（布和装备各只有一份选中态，互斥）
- 拖装备期间 `BeginItemDrag` 收起操作条，松手 `EndItemDrag` → `refreshActionBar()` 按落点之后的选中态复原
- `refreshActionBar`（UIShopPanel.cs:899）统一处理布与装备：
  - `target = m_selectedPlate ?? m_selectedItem`，再用 `Model.Plates.Contains / Model.Items.Contains` 验它还在不在网格上；不在就条子、外框、详情一起收掉（卖掉 / 拆走 / 挤进暂存架都走这条）
  - 第二条文案：布显示「拆下」，装备显示「取下」，本质同一件事（都进暂存架）
  - 第三条文案：`SellPriceOf` 只认布料总表，装备算不出回收价 → 恒显示「不回收」且 `interactable = false`（数据现状，不是 bug）
  - 第一条：`RotateButton.interactable = target.CanRotate`，1x1 的东西键是灰的
  - 条子本体也接了点击（`handleClearPlateSelection`），点空白处直接取消选中
  - 每次重铺都会 `SetAsLastSibling()`，否则新插的物品视图会把条子盖住
- `handleRotateClicked / handleStashClicked / handleSellClicked` 三条入口各按「选中的是布还是装备」分叉，装备分支是本轮新加的

### 3.2 背包 ⇄ 暂存架双向拖拽

背包 → 暂存架（下拉到架子面板）：

- `IsPointerInStash(screenPoint)` 用 `RectTransformUtility.RectangleContainsScreenPoint` 判 `Bg/Panel_Storage`，落点判据是**指针位置**而不是物体中心，拖出画面边缘更直觉
- `UIShopItemView.OnEndDrag`：先 `BeginItemDrag` → 若 `IsPointerInStash` 则 `TryStashItem(m_item)`，否则按原逻辑算锚点 `TryMove`，末尾一律 `EndItemDrag`
- `UIShopPlateView.OnEndDrag` 同样先判 `IsPointerInStash` → `TryStashPlate`（布拖走时压着无底可托的装备会成孤儿进架，这是 `BackpackModel.TryMovePlate` 的既有设计）
- `TryRemoveItemToStash`（RunBackpack.cs:222）：`StashRemaining < 1` 时 `QLog.Error` 并返回 false；装备不托东西，摘走不会有谁悬空，所以不用像布那样算孤儿
- 收不成也要 `refreshBackpack()`，视图才会把东西弹回原格

暂存架 → 背包（按落点摆 + 幽灵预览）：

- `SetStored(BackpackItemInstance, int stashIndex, IShopBackpackHost)` 取代上一版的 id 传参，格子上直接握着实例，拖拽时不必回查
- `OnBeginDrag`：`m_wasDragged = true` → `UIShopShapeGhost.Build` → 立刻 `moveGhost`，一上手就有预览
- `moveGhost`：`TryPointerCell` 拿到吸附格就 `PlaceAt`，指到网格外 `root.SetActive(false)`（幽灵整体藏起来而不是逐格改色，避免残留半格）
- `OnEndDrag`：先 Recycle 幽灵 → `TryPointerCell` 失败就直接 return（东西留在架上）→ 成功才 `TryPlaceFromStashAt`
- `TryRecallFromStashAt`（RunBackpack.cs:197）：按 Kind 分叉走 `TryPlacePlate` / `TryPlace`；摆不成只是留了个没落地的锚点，两条放置入口都会自己重算，不必回滚，返回 false 让东西原样留在架上
- `OnPointerClick` 保留「按一下自动找落点取回」，但 `m_wasDragged` 为真时先吞掉，避免拖完被误判成按一下
- `OnDisable` 里补 `Recycle(m_ghost)`：面板关掉或格子被隐藏时走不到 OnEndDrag，不补就会把幽灵永久留在场上

### 3.3 UIShopShapeGhost（新文件）

- 节点名常量：`ROOT_NAME = "Ghost_Shape"`、`BLOCK_NAME = "Img_GhostCell"`、`FACE_NAME = "Img_GhostFace"`
- `Build(item, color, pitch, cellSprite, layer)` 按实例的形状与朝向铺出一整块半透明预览，底图与真格子同一张 sprite，所以轮廓和场上格子完全一致
- 常量：`RIM_THICKNESS = 4f`（亮面相对暗边内缩 4px）、`RIM_DARKEN = 0.28f`（暗边 = Color.Lerp(色, black, .28)）、`GHOST_ALPHA = .86f`
- `PlaceAt` 只挪根节点 anchoredPosition，格子的相对排布在建的时候一次性算好
- `Recycle`：**先 `root.SetActive(false)` 再销毁**，编辑模式下 `Object.Destroy` 会报 `Destroy may not be called from edit mode!`，所以按 `Application.isPlaying` 分叉 Destroy / DestroyImmediate

## 五、编辑模式拍 UI 的配方（沿用 12 号 §五，本轮只补两处）

配方本身照抄 12 号：临时正交相机（size 960 / aspect 1080÷1920 / near .01 / far 500 / SolidColor / pos = canvas 中心 / rotation identity）+ `renderMode = ScreenSpaceCamera` + **`worldCamera = cam`（漏了整帧全空）** + planeDistance 100 + scaleFactor 1，收尾一定要还原 canvas 四项并 DestroyImmediate 相机与面板，否则场景变脏。

本轮驱动方式换成走真实入口，不再手改模型：`panel.SelectItem(rod)` → `rotateBtn.onClick.Invoke()` → `stashBtn.onClick.Invoke()` → `slot.OnBeginDrag/OnDrag/OnEndDrag(new PointerEventData(EventSystem.current))`，`ev.position` 直接取目标 `Transform.position` 的 xy（Overlay + scaleFactor 1 下屏幕坐标 == canvas 世界 xy）。

本会话新撞的坑：

- `BackpackItemInstance` 上**没有** `Definition.Rows / Definition.Columns`，要用 `Shape.CellCount`、`OrientationIndex`、`AnchorColumn`、`AnchorRow`
- `assets_refresh` 的 `options` 必须传**字符串枚举名**（`ForceSynchronousImport`），传数字会参数校验失败
- `PrefabUtility.InstantiatePrefab` 出来的面板实例若不清掉，`Game.unity` 就是脏场景，tests-run 一类工具会直接拒

**教训（下次直接照做）**：行级 splice 改完必须扫一遍「连续重复行」，尤其 `if` / `else` 成对出现的地方。本轮 bug 2 就是这么来的，而且肉眼极难看出——图上只是「架上多留了一件」，很容易被当成设计。

看着像 bug 其实不是：

1. **shot2 里 r1 两格发暗**：不是鱼竿多占了格，是操作条压在那儿（条的暗底 `RGBA(63,54,43)`）。别拿这张去判 occupancy。
2. **条上第三键写「不回收」**：`ShopService.SellPriceOf` 只认 `ClothPieceDef`，装备恒返回 0 → 显示「不回收」并把键置灰。这是数据现状，本轮没擅自给装备编回收价。
3. **探针 s4 报 ghost=False**：探针自己 `GameObject.Find` 用了错名 `Shape_Ghost`（真名 `Ghost_Shape`）。幽灵本身渲染正常，shot3 可直接看到。
