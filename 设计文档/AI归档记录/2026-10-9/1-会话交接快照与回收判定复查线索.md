### 剩下的主要嫌疑（都要先取证再问用户）

```text
H1  捕获点在 Awake 里一次算死：HookViewController.setupCaptureOffset()
    Assets/Scripts/Module/Fish/View/HookViewController.cs:141，只在 Awake:82 调一次
    取 Lure 子树 Renderer.bounds 的最低点，再换算成父空间偏移
    运行时钩子或 Lure 一旦被旋转 / 换 sprite / 改缩放，这个点就和肉眼看到的钩尖脱节
    CaptureDepth = Depth - m_captureOffset.y（:53），点偏下就表现为「鱼贴在钩上却判不到」
H2  鱼身盒的轴朝向：FishFactory 量盒时依赖写进 localRotation 的朝向（FishFactory.cs:31 注释）
    而 FishAiService.cs:84 每帧按方向写 Euler(0, ±90, 0)
    朝向翻转后 halfX / halfY 若没跟着换，竖向判定范围会塌成窄带，回收时最容易擦身而过
H3  HookTip 找不到时 LogError 并退回钩子根节点（HookViewController.cs:143-152）
    退化的根节点比钩尖高一个钩身，观感就是「穿过去了」，进 Play Mode 先看有没有这条报错
```

建议的取证手法（**别一上来就改判定公式**）：Play Mode 里当 `ResolveContact` 没命中但鱼就在附近时，临时打印 `CaptureHorizontal / CaptureDepth`、鱼心、`halfX / halfY`、`distance`、`reach`，跑一趟回收阶段看差在哪个轴。拿到数据后再把「捕获点该不该每帧重算」这个取舍抛回给用户。

## 八、工具坑（省得下个会话重新试）

```text
PowerShell 的 Remove-Item 走沙箱会被拒，删临时文件改用 node_repl 的 fs.unlinkSync
数 prefab / scene YAML 里的组件数量：用 [System.IO.File]::ReadAllText + [regex]::Matches，别用 Select-String 猜
Select-String -Path "目录\**\*.cs" 在 Windows PowerShell 5.1 里不递归
  要用 Get-ChildItem -Recurse -Filter *.cs | Select-String
script_execute 里 SceneManager 要 using UnityEngine.SceneManagement
  PrefabStageUtility 在 UnityEditor.SceneManagement
要在 Play Mode 里抓 UI 截图：反射遍历 AppDomain 拿面板实例 -> StartCoroutine
  -> WaitForSecondsRealtime -> ScreenCapture.CaptureScreenshot 到 .codex/tmp，回复里用绝对路径嵌图
node_repl 有时会报 failed to write kernel assets（os error 3），此时回退 PowerShell 打补丁：
  [IO.File]::ReadAllText -> .Replace -> 断言（锚点唯一 / fence 偶数 / 无裸 LF）-> WriteAllText(UTF8 无 BOM)
```
