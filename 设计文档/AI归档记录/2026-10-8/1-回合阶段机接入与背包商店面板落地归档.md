## 二、本次确认的设计 / 协作偏好

### 背包的口径（用户拍板，后续不许自行改）

```text
形态        俄罗斯方块式占格，物品是「形状」不是「单格」，多数形状可旋转
容器        6 列 x 5 行 = 30 格（早期 3x3 方案作废）
空格外观      半透明圆角底图，只表达「这个位置能放」，不是实体块
锁格外观      暗色纯色块，sprite = null
仓库/暂存架   按件计，不参与网格，容量 5；正常设计该是无限，用户认可先限量 5 格
开局         白色品质「教学鱼竿」，竖条 2 格，配置写死自动落位
形状来源      不要一格形状（没有取舍）；不要太大块（背包尺寸很小）；不要纯黑方块（看不清）
```

### 回合与经济的口径

```text
每回合固定 N 次下潜，N = 3，取自会话配置；后续由钓杆等级 / 物品 BUFF / 藏品提升
每回合先进商店再进钓鱼，上一回合卖鱼所得金币在商店花掉
鱼的价值按品质定价（品质越高价值越高），钓杆后续可加倍率
金币银行跨回合保留、不过期；回合目标价值不继承，超额部分不顺延到下一回合
```

### 协作偏好（延续 10-6，仍然有效，并新增两条）

- 优先用 Unity MCP 操作编辑器，**不手改 `.unity` / `.prefab` / `.asset` YAML**
- 不在工程里留一次性 Editor 工具脚本，临时验证走 `script-execute`，跑完即销毁
- 范围严格执行「其他的别做」，不顺手重构
- 用户会在 Rider 实时编辑：动手前重读磁盘，改后提醒 `File -> Reload All from Disk`
- 改了 `.cs` 才附「📝 代码变更摘要」；纯归档要明说未修改代码
- 私有字段 `m_` + camelCase（含 `static`/`readonly`），`[SerializeField]` 用 PascalCase，`const` 用 UPPER_SNAKE_CASE
- **新增：注释里不许出现「设计文档1 / 2 / 3」这类编号口径**，用户不会提交设计文档，注释必须自解释
- **新增：预制体不能只靠运行时代码动态生成，至少把外观相关的东西（如锁格半透明）落到预制体里，用户要能在编辑器里看到效果**
- **新增：碰到不确定的取舍先问，不要盲目改**

## 四、关键架构边界

```text
FishingScene        只挂引用（4 个 SO + 3 个场景引用），不写玩法
FishingController   唯一裁决者 + 唯一阶段切换者，商店/钓鱼的进出只在这里发生
UIShopPanel         只读表现 + 只广播「离开商店」，绝不自行决定去哪一层
BackpackConfigSO    只读配置；BackpackModel/RunBackpack 纯 C# 状态，不认识 Unity 对象
UIShopSlotItem      位置与尺寸交给 GridLayoutGroup，脚本只切底图与颜色
```

- **事件边界**：商店面板与控制器之间只有 `ShopExitRequested` 一条线。以后要加「买完直接下潜」「刷新商品」等动作，仍旧是面板发事件、控制器裁决，别把 `enterFishingPhase` 暴露给 UI
- **UIManager 语义坑**：`Open<T>()` 命中缓存时**只有 `!gameObject.activeSelf` 才会再跑 `OnOpen(args)`**；`Hide<T>()` 只 SetVisible(false) 不触发 `OnOpen`；`Close<T>()` 走 `OnClose` + 隐藏 + `Controller.OnViewClosed`。所以 `UIShopPanel` 用 `Close`（回钓鱼）而 `UIFishingHUD` 用 `Hide`（进商店），别顺手对调
- **每回合重建面板数据**：`UIShopPanel.OnOpen` 里 `fillBackpack()` 用 `GetComponentsInChildren` 顺序 + `m_grid.constraintCount` 反推行列，节点名是 `Slot_{row}_{col}` 共 30 个 + `Storage_0..4`。预制体里格子顺序一旦变，行号就会算错，这条比看上去脆
- **sortingOrder**：HUD 10 / RoundHUD 20 / Shop 60 / Result 100。商店盖住 HUD 是靠 60 > 10，不是靠 Hide
- **`IFishingStats` 换实现**：P1 接背包属性加成的口子已经立住（`DefaultFishingStats` 透传 `HookConfigSO`），把 `RunBackpack` 的加成汇进 stats 即可，调用方不改
