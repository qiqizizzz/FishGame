## 三、图标从哪来：All Icons.png 的网格实测

工程里原本没有现成的「禁止」图。`Assets/Art/UI/HUD/All Icons.png`（288x48，guid `68a49f66ddc013842ba448ec37fd1283`）当时**全工程零引用**，正好含这枚 glyph。逐格统计 alpha 实测出的排布：

| 轴 | 结论 |
| --- | --- |
| 间距 | pitch = 16px，18 列 x 3 行 = 54 格 |
| 明度 | 每行都是 6 种形状 x 3 种明度；col 0-5 = 浅 `#FBFBF6`，col 6-11 = 中 `#E8CFA6`，col 12-17 = 深 `#C49A6C` |
| 形状（按纹理 y，y=0 在**底**） | y=0..15 → plus, minus, home, check, cross, **prohibited**；y=16..31 → exclaim, dollar, cart, flag, trophy, crown；y=32..47 → gamepad, invader, skull, gear, question, medal |
| 明度组内的形状顺序 | 浅组与中组同序；深组相对浅组**错位 3 格**，别照 col-6 直接推 |

> 上一轮记录把这三行按「PNG 从上往下」编号，写成 row0=gamepad、row2=plus 系。**纹理坐标要反过来**：视觉最下面那行才是 y=0。本轮就是靠这条差异才没裁错格。

「禁止」= 圆圈加左上一道斜杠，在浅组里是 **col 5 / y 0..15**，紧贴 alpha 包围盒是 `rect=(2,2)-(13,13)`，即 **12x12**（不是上轮估的 14x14）。

### 3.1 为什么没走「拆 sprite sheet」

想直接给这张共享表补 `spriteSheet` 子资产，两条路都堵：

- `TextureImporter.spritesheet` 在本版本已移除 → CS0618；`imp.spriteMeshType` 也不存在 → CS1061
- `UnityEditor.U2D.Sprites.SpriteEditorDataProvider` 在 2022.3.52f1 里遍历全部程序集也 **取不到类型**（不是 public）

剩下的路是手写 `.meta` 的 `spriteSheet` YAML（`internalID` 与 `nameFileIdTable` 要自己编），风险高、收益低。于是走**裁成独立 PNG**这条：与本工程既有的 `Assets/Art/UI/Rod/rod_t_*.png` 同一套做法，不碰共享表的 importer。

### 3.2 裁图管线（可复用）

`AssetDatabase.LoadAssetAtPath` → `RenderTexture.GetTemporary` → `Graphics.Blit((Texture)t, rt)`（**必须写 `(Texture)`，写 `(Object)` 会 CS1503**）→ `RenderTexture.active` → `read.ReadPixels` → 取 `GetPixels32` 算包围盒 → `EncodeToPNG` → `File.WriteAllBytes`。
读到的 `Color32[]` 索引 0 是**左下**，与 PNG 的上下关系相反，摆坐标时最容易翻车。

## 四、关键设计决定

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 已售出还能不能点 | **不能**，卡保持 `interactable = false` | 卖完的东西没有「详情」可看，价钱与描述都是空转 |
| 预览区怎么表达 | 图标与异形布**都收掉**，只留 `Img_SoldOut` | 压暗的商品预览仍然在描述一件买不到的东西，等于骗眼睛 |
| 图标取哪个明度 | 取**浅色**那格，颜色交给 `Image.color` 调 | 近白底乘任何色都精确，中/深底会被二次压暗，改观感不用重裁图 |
| 图标染色 | 预制体上写死 `#4A3220 a8C`（55% 不透明深棕） | 与名称深色同源，压在木色卡上「在但退后」；价钱那行已经是 `PriceUnaffordable` 红，图标不该再抢 |
| 图标尺寸 | 36x36 居中在 48 高的预览带里（`pos.y = -16`） | 铺满 48 会把一张卖完的卡喊得比在卖的还响 |
| 采样方式 | `filterMode = Point`、`preserveAspect = true`、不开 mipmap、`maxTextureSize = 128` | 12x12 要放大 3 倍，线性采样会糊成一团灰 |
| 名字与价钱两行 | **照旧保留** | 「哪件卖完了」比「这里空了」信息量大 |
| 拖已售出的卡 | 起拖也**不给幽灵** | `Button.interactable = false` 只关掉按钮自己的指针回调，同物体上的 `IBeginDragHandler` 照样收得到 —— 全靠 `OnBeginDrag` 里 `m_entry.IsSold` 那道早退挡着，别以为按钮禁了就安全 |
| 详情小窗的价钱 | 去掉 `showPrice` 开关，**恒显** | 能点开的一定还在卖，那个分支是死的 |
| 布吸附的坐标 | `RoundToInt(free.y / pitch) * pitch`，**y 不取负** | `anchoredPosition.y` 本来就是负的，再取负整块布翻到网格上方（上轮踩过） |
| 布要不要逐格合法性染色 | **不要** | 布没有「这一格能不能压」的中间态，落点不成靠 `TryMovePlate` 重铺把布弹回原位；装备那套 `refreshDragTint` 是它自己有覆盖/缺格两种判定才需要的 |

```csharp
Vector2 free = pointerInGrid(eventData) - m_grabOffset;

if (m_host.TryPointerCell(eventData.position, out _, out _))
    m_rect.anchoredPosition = new Vector2(Mathf.RoundToInt(free.x / m_pitch) * m_pitch,
        Mathf.RoundToInt(free.y / m_pitch) * m_pitch);

    m_rect.anchoredPosition = free;
```

## 七、要你在 Play 里验的

1. 买走一件 → 那张卡的预览区变成一枚棕色禁止圈，名字还在，价钱那行写「已售出」
2. 点已售出的卡 → **什么都不会发生**（不浮小窗、不起幽灵）
3. 在卖的装备卡 → 仍是图标；在卖的布卡 → 仍是异形格预览，颜色没被压暗成灰
4. 布在网格内拖 → 一格一格跳，不再半格骑在两条缝上；拖出网格 → 恢复跟手自由挪
5. 布吸附后松手在摆不开的位置 → 仍然整块弹回原位（吸附不该改变这条）
