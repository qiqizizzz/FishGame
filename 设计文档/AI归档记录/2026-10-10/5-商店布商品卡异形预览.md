# FishGame 商店布商品卡：方块改成真实异形预览

> 上一轮：2026-10-10/4-背包内拖动吸附网格与叠加格底图.md　　本轮日期：2026-10-10　　基线 HEAD：b17d038「同上」

## 一、记录范围

货架上的布商品卡原本只染一个 48x48 的纯色方块（`ClothPieceDef.Icon` 恒为 null，`Img_Icon` 没底图就画成白方块），
二格和六格看着一样大，方向也完全看不出来。本轮把这块地方改成**按真实异形逐格画出来的预览**。

装备卡一行没动，照旧贴图。

## 二、用户诉求原话

- 「把这些布改成实际的多少格以及什么颜色以及方向的预览图，现在的只是一个方块，很难看」

## 三、方案选型：为什么不生成贴图

| 方案 | 结论 |
| --- | --- |
| 离线给每个「布色 x 形状」生成一张 PNG | 否：15 块布 x 5 个形状 = 75 张，形状一改就得重生成，还要维护一堆资产 |
| 运行时逐格克隆 UI 格子 | **用这个**：零新增资产、零重生成、朝向直接读 bitmask，且和背包静止态的格子完全同源 |

工程内已有同模式先例：`UIShopPlateView.showClothCell`、`UIShopShapeGhost.showCell` 都是逐格克隆。

## 四、关键设计决定

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 单格尺寸 | 整面货架统一 `CellSize=15`、`CellSpacing=1` | **统一才诚实**：6 格看着就该比 4 格大。若按形状自适应撑满，slab_6 的格子反而比 block_4 小，等于骗人 |
| 预览带 | 新增 `Node_ClothShape`：190x48，锚点/轴心顶部居中，`anchoredPosition=(0,-10)`，与 `Img_Icon` 同位同高 | 卡片**不能加高**：`Panel_Shop` 940x228、`Row_Goods` 868x150 在 y=-66，底部只剩 12px |
| 为什么是 15 | 3 格 = 15x3 + 1x2 = **47 <= 48** | 现有 5 个形状最大包围盒就是 2 宽 x 3 高，48 是天花板 |
| 层数 | **一层**，不要拖拽幽灵那套 rim+face 两层 | 背包静止态的布就是一张 `Image` + `Square Buttons 26x26_1` + 布色（`UIShopSlotItem.SetCloth`），预览要和它一个样 |
| 底色 | `entry.IsSold ? m_soldTint : goodsColor` | 已售出沿用卡片原有的压暗灰 `0x8C8C8C` |
| 朝向 | `ShapeAt(tier).OrientationAt(0)` | 买入手时 `BackpackItemInstance.OrientationIndex` 就是 0，**所见即所得**，卡上不会摆出买回去摆不出的形 |
| 显隐 | `Kind == Cloth` -> 藏 `Img_Icon` 显预览；否则反之 | 同一块地方两类商品互斥，不会叠出两张脸 |

## 五、改了什么

### 5.1 新增 `Assets/Scripts/UI/Shop/UIShopClothShape.cs`

挂在预览带上，按形状位图逐格克隆 `Cell_Template`：

```csharp
float pitch = CellSize + CellSpacing;
float bboxWidth  = shape.Width  * pitch - CellSpacing;
float bboxHeight = shape.Height * pitch - CellSpacing;
float left = -bboxWidth * 0.5f;                       // 带子轴心在顶边中线，x 以中线对称
float top  = (m_rect.rect.height - bboxHeight) * 0.5f; // y 从顶边往下量
foreach (Vector2Int cell in shape.Cells())
    cellRect.anchoredPosition = new Vector2(left + cell.x * pitch, -(top + cell.y * pitch));
```

- 格子**只创建不销毁**：`m_cells` 池 + `m_cellsUsed`，卡片在复用池里反复换货，遇到更大的形状再补，换小的只是 `SetActive(false)`
- `Setup(GridShapeSO, Color, Sprite)`：模板为 null 时 `QLog.Error` 报错并清空，不静默跳过
- `cellSprite` 传 null 才沿用模板自带底图 —— 面板传进来的是 `m_slots[0].EmptyCellSprite`，和真格子同一个来源

### 5.2 `UIShopGoodsItem.cs`

- 新增 `CLOTH_SHAPE_PATH = "Node_ClothShape"` 与 `m_clothShape`，走 `FindComponent`（缺了当场报错）
- `Setup` 尾部加参数 `Sprite cellSprite`
- `applyIcon(icon, isSold, goodsColor)` -> `applyVisual(entry, goodsColor, cellSprite)`，按 `Kind` 分两条路
- 文件头两行注释重写，`goodsColor` 的 param 注释顺手改掉过时的「阵营纸色」说法

### 5.3 `UIShopPanel.cs:1453`

`goods.Setup(...)` 补上面板里**已有**的 `m_cellSprite`（读自 `UIShopPanel.cs:269`），真格子 / 幽灵 / 叠加格 / 卡面预览从此一张图。

### 6.3 离屏渲染

`C:/Users/wuqian/AppData/Local/Temp/cloth_preview.png`：五张布卡 + 一张装备卡并排，
布卡分别是 2x2 / corner / 1x2(灰=已售) / 1x3 / 2x3，装备卡图标不变。

**踩过的坑**：第一版预览全挤在卡片左上角。原因是 `Cell_Template` 锚点写成了 `(0,1)`（带子左上角），
而代码里 `left = -bboxWidth * 0.5f` 是按**带子中线**算的。锚点改成 `(0.5,1)` 后归位。
以后碰到「位置整体偏半个容器」，先查锚点，别改代码里的符号。

## 七、当前尚未完成 / 待用户验

1. **Play 模式没实测**：Game 视图最小化时 `frameCount` 不推进，编辑模式跑不了完整 UI 流程，得用户自己开商店看一眼
2. 单格 15px 是按「最大形状必须塞进 48 高的带子」倒推出来的硬上限。要更大只能**加高卡片**，而加高会顶到 `Row_Goods` 底部只剩 12px 的空间，得先动整块商店面板的布局
3. 暂存架 `UIShopSlotItem.SetStored` 里一块布进架子仍是「整格染一个色 + 文字标签」，同样是方块 —— 可以复用这套预览，**等点头再动**
4. 详情小窗 `UIShopDetailWindow` 同理，也可以放异形预览
