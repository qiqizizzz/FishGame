# FishGame 商店：商品卡只留预览与价钱，拖进有位置的地方才算买成

> 上一轮：2026-10-10/5-商店布商品卡异形预览.md　　本轮日期：2026-10-10　　基线 HEAD：feb2140「同上」

## 一、记录范围

商品卡原来把加成文字直接摊在卡面第三行，字多就省略号；购买是「点一下自动找个位置放下」，玩家点完只看见东西凭空出现在别处。
本轮把这两件事分开：**点击 = 看详情**（名字 + 描述 + 右上角价钱），**拖拽 = 买**，而且落点由玩家自己拖出来。

顺带把上一轮留着的两个「等点头再动」也做了：暂存架里的布改成真实异形预览、详情小窗里也画出这块布的形。

## 二、用户诉求原话

- 「那个商品那边下面就别写商品的详细信息了，写个图标和价钱就行，然后点击商品可以看详细信息（与已经买到的物品不同，这个会显示名字，描述以及右上角的金钱）」
- 「然后购买商品改为拖动商品到仓库或者背包有位置的地方就购买成功啦，你看看怎么优化一下」
- 「1.可以 2.可以」—— 对上轮第七节的两条待点头项：**同意**暂存架的布画异形、**同意**详情小窗放异形预览

## 三、方案选型：购买为什么挂在拖拽上

| 方案 | 结论 |
| --- | --- |
| 卡上留「购买」按钮，点了系统自动找位置 | 否：位置由系统挑，玩家看着它凭空落在别处，跟背包「自己铺格子」的核心手感正好相反 |
| 点一下买 + 拖一下买，两种手势都能成交 | 否：同一张卡两种结果，误触一次就扣一次钱，而且没人能记住哪条是哪种 |
| **点击只看详情，拖到落点才成交** | **用这个**：手势与语义一一对应 —— 看 = 点、买 = 拖，钱只在拖成功那一帧动 |

落点只有两处：网格（按拖出来的那一格入手）与暂存架面板（整块面板都算落点，直接进架）。两处都没挨上 = 没买，一分不扣。

## 四、关键设计决定

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 落点语义 | 只认玩家拖出的那一格，铺不开就整笔作废 | 商店这条路**不替玩家另找位置**、也不自动退进暂存架。「买了 A 却落在 B」比「没买成」更让人火大 |
| 铺不开的结果 | `ShopBuyResult.BackpackFull` → **改名 `NoRoom`** | 旧名字只说「背包满」，而现在真实语义有两种：这一格铺不开 / 架子没空位。名字不改，日志就在骗人 |
| 入手 API | 新增 `RunBackpack.TryAddItemAt(def, tier, col, row)` 与 `TryAddItemToStash(def, tier)` | 老的 `TryAddItem` 是「行主序自动扫锚点 + 塞不下退架子」，商店要的恰好是反面。内部拆出只回真假、不喊错的 `tryPushToStash`，自动那条链继续用会喊的 `pushToStash` |
| 扣钱三步 | `ShopService.tryComplete(entry, run, backpack, place)` | 扣钱 → `place()` → 不成原额退回、成了才 `MarkSold`。`place` 只回答「按这个落点入不入库」，账全记在一处，不会出现钱花了东西没影 |
| 买不起能不能拖 | **能起拖**，但整块幽灵判红 | 玩家得能拖着它比一比才决定买不买。判红走 `IsPreviewCellValid`：`m_pendingPurchase != null && Price > m_run.Coins` 时每一格都回 false |
| 拖拽途中能否旋转 | **不支持** | 商品还没到手，网格里没有它的实例，旋转要先有落点；再叠一个键还会跟落点判定搅在一起 |
| 商品卡版面 | 预览/图标 + 名字 + 价钱，**删掉 `Txt_Detail`** | 「+2 拾取 / -1 阻力」这类多字加成在 202 宽的卡面上永远写不完，点开详情才塞得下 |
| 详情小窗 | 复用同一扇 `UIShopDetailWindow`，商品只多「右上角价钱 + 布形预览」 | 拆成两扇预制体，改一次字号要改两处 |
| 窗子随内容长高 | 有预览带时 `m_detailHeight = 预制体高 + DETAIL_PREVIEW_EXTRA(38)` | 预览带锚在**底缘往上 6px** 铺 48 高。132 的窗高里它和描述行会重叠 24px；加高到 170 后描述底边 -17、预览顶边 -31，留 14px 缝 |
| 名字行避让价钱 | `setDetailNameReserve(价钱实测宽 + 16 + 12)` | 价钱是顶对齐右对齐，名字是左右拉伸，不让位长名字会钻进价钱底下 |
| 小窗跟随位置 | 商品那份浮在**被点那张卡的正上方**，顶上顶不下就翻到卡下方 | 卡片下面紧贴面板底缘与按钮条，那个位置塞不进一扇窗。用 `GetWorldCorners` 搬到背景层坐标系 |
| 拖商品提层 | 复用 `raiseBackpackPanel` / `restoreBackpackPanel` | 拖出去的东西原本会钻到仓库与商店底下（上轮遗留）。提层只记第一次的 `siblingIndex`，重复调用不会把提层后的序号当原序号 |
| 布与装备的落点规则 | 沿用同一套 `IsPreviewCellValid`，商品不额外开后门 | 布只看「这格有没有别的布压着」，装备在下头不算冲突；装备反之，必须有布垫着 |

## 五、改了什么

### 5.1 `Assets/Scripts/Module/Shop/Model/ShopBuyResult.cs`

`BackpackFull = 3` → `NoRoom = 3`，注释改成「拖出来的落点铺不开，或暂存架没有空位，钱已原额退回」。

### 5.2 `Assets/Scripts/Module/Shop/Service/ShopService.cs`

- `TryBuy` 拆成 `TryBuyAt(entry, run, backpack, anchorColumn, anchorRow)` 与 `TryBuyToStash(entry, run, backpack)`
- 两者都只写一行 `place` 闭包，公共账目全在新增的 `tryComplete`
- 文件头补一行「买入落点由玩家在界面上拖出来定，铺不开与架子满都算没成交，钱原额退回」

### 5.3 `Assets/Scripts/Module/Backpack/Model/RunBackpack.cs`

新增两个「按指定落点入手」的公开方法，与自动落位那条链完全分开：

```csharp
return definition.Kind == BackpackDefKind.Cloth
    ? m_model.TryPlacePlate(instance)   // 布：只看这一格有没有别的布
    : m_model.TryPlace(instance);       // 装备：必须有布垫着
```

`pushToStash`（会喊 Error，自动链用）与 `tryPushToStash`（安静回真假，商店链用）分离，
免得商店架子满了时模型层先喊一句「装不下」、面板又补一句「钱已退回」。

### 5.4 `Assets/Scripts/UI/Shop/IShopBackpackHost.cs`

新增 5 个成员，商品卡只通过它们与面板说话，自己一律不碰钱与网格：

`ShowGoodsDetail(entry, cardRect)` / `BeginGoodsDrag(entry)` / `EndGoodsDrag(entry)` /
`TryBuyGoodsAt(entry, col, row)` / `TryBuyGoodsToStash(entry)`

### 5.5 `Assets/Scripts/UI/Shop/UIShopGoodsItem.cs`

- 删掉卡面第三行 `Txt_Detail`，版面只剩预览 + 名字 + 价钱
- 实现 `IBeginDragHandler/IDragHandler/IEndDragHandler`：起拖时造一个**临时** `BackpackItemInstance` 交给 `UIShopShapeGhost.Build`，与暂存架那条幽灵完全同一套
- `OnEndDrag` 的顺序：收幽灵 → `EndGoodsDrag`（还层）→ 先判暂存架再判网格
- 买不起仍允许起拖；价钱染红走 `UIShopQuality.PriceUnaffordable`（`0xB03A2E`），颜色从预制体读回默认值，不写死
- 原来的 `m_dragFrame` 帧号方案**换掉**，见第七节

### 5.6 `Assets/Scripts/UI/Shop/UIShopPanel.cs`

- 详情链路认出「还没到手的这一件」：`m_detailGoods` + `m_detailCardRect`，与已入手的 `m_detailTarget` 各走各的显隐
- `ShowGoodsDetail` 里先看商品**不占用选中态**（`m_selectedPlate/m_selectedItem` 清空）—— 东西还躺在货架上，不该把网格里的选中物顶掉
- `BeginGoodsDrag`：记 `m_pendingPurchase`、提层、收起操作条与小窗；`EndGoodsDrag`：还层 + 重算操作条，成没成都走这一条
- `handleBuyResult(entry, result, toStash)`：Success 才 `clearDetail + refreshAll`；NoRoom 只 `refreshCounters`（钱退回了但货架没变，重铺整个面板会把幽灵残留牵进来）
- `setDetailClothPreview / clearDetailClothPreview`：背包里的布按 `item.OrientationIndex` 画（可能已被转过向），货架上的按 0 画（买入时入手朝向就是 0，所见即所得）
- 宽度算法把价钱也算进去：`max(名字宽, 描述宽) + 38 + 16 + priceReserve`，夹在 340~520

### 5.7 暂存架的布画异形

- `UIShopSlotItem.SetStored` 分叉：装备仍整格染品质色；布退回空格那点淡底 `EmptyColor` + `CellSprite`，异形交给 `Node_ClothShape`
- `UIShopClothShape.Setup` 加一个 `orientationIndex` 重载（旧的三参重载转调 `Setup(..., 0)`），暂存架要照这块布**此刻**的朝向画
- `Clear/SetLocked/SetEmpty` 三处各自补 `hideClothShape()`，复用格子不能带着上一件的形
- 预览带是**可选节点**（`FindNode` + 判空），仓库格缺了它只退回旧的整格染色，不当配置错误报错

## 七、拖完再点会被吞（本轮附带修掉的隐患）

读 `Library/PackageCache/com.unity.ugui@1.0.0/Runtime/EventSystem/InputModules/` 得到两条权威结论：

1. `StandaloneInputModule.ProcessDrag` 里有 `IsPointerMoving()` + `ShouldStartDrag(pressPosition, position, pixelDragThreshold, useDragThreshold)` 双重门 —— **OnBeginDrag 只在真拖过阈值后才触发**，纯点击不会触发。所以「点商品看详情」「点暂存格取回」这两个手势是成立的。
2. `PointerInputModule.ReleaseMouse` 的顺序是 **pointerUp → pointerClick → drop → endDrag**，即**点击先于 OnEndDrag**。

原来的隐患：`m_wasDragged=true` 只被 `OnPointerClick` 清。可**松手在网格外时根本收不到 click**
（`pointerClick != GetEventHandler(currentOverGo)`），标记就粘在 true 上；卡片从池里复用时更糟 —— 下一次真点击被白吞一次。
`UIShopGoodsItem` 那版用 `m_dragFrame` 记帧号绕过，但 Game 视图最小化时 `frameCount` 不推进，方案本身就不可靠。

统一改成：**OnBeginDrag 置 true，OnEndDrag 与 OnDisable 都清**（endDrag 永远收得到，且它在 click 之后，同帧的拖后点击照样被吞掉）。

| 文件 | 加的清理点 |
| --- | --- |
| `UIShopPlateView.cs` | `endDrag()` 里 `m_isDragging=false` 之后（OnDisable 走同一条链） |
| `UIShopItemView.cs` | `OnDisable` 与 `OnEndDrag` 尾部各一处 |
| `UIShopSlotItem.cs` | `OnDisable` 与 `OnEndDrag` 的 `m_ghost=null` 之后 |
| `UIShopGoodsItem.cs` | 删 `m_dragFrame` 换 `m_wasDragged`，`Setup`/`OnDisable`/`OnEndDrag` 三处清；顺手补上文件末尾缺失的换行 |

反射复核：四个类型都是 `m_wasDragged=True m_dragFrame=False`。

## 八、当前尚未完成 / 待用户验

**Play 模式没实测**：Game 视图最小化时 `frameCount` 不推进，编辑模式跑不了完整 UI 流程。请进 Play 逐条看：

6. 商品卡版面 → 只剩预览 + 名字 + 价钱，没有第三行
