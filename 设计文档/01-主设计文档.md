# 二、参考录屏逆向拆解

以下全部为逐帧观测结论，非猜测。

## 单局循环时间轴

| 时间点 | 画面 | 含义 |
| --- | --- | --- |
| 0 – 19s | 圆角面板内播放动画演示，底部滚动三条引导文案，右上角 X 关闭 | 首次进入的**玩法教学弹窗**，用动画而非文字教程 |
| 20 – 22s | 切到冰钓水面场景，屏幕中央大号数字 2 | 单局**开局倒计时**（3-2-1） |
| 24 – 46s | 水下垂直井道，鱼钩下潜再回收，HUD 数值变化 | 第 1 局核心玩法 |
| 48 – 51s | 回到水面，飘出多个 `+10`，随后弹出「本次收获」面板 | 结算与奖励飘字 |
| 52 – 78s | 倒计时 3 → 1 → 再次下潜 | 第 2 局，验证「继续体验」直接重开 |
| 80 – 90s | 再次「本次收获」面板，随后黑屏 | 结束 |

结论：**引导 → 倒计时 → 单局 → 结算 → 再来一局** 的闭环，没有关卡地图与 meta 界面出现在录屏里。

## 场景构成

- **水上装饰层**：雪山远景、夜空与星点、蹲在冰洞旁的渔夫（厚冬装）、风向袋、马灯、木箱、冰面
- **水下玩法层**：蓝色水体，左右两侧冰壁构成一条**垂直井道**，鱼群分布在井道内不同深度
- 水面线是明确的视觉与逻辑分界：钩子出水即视为回收完成

## HUD 三行计数（左上角，图标已放大确认）

| 行 | 图标 | 观测取值序列 | 语义判定 |
| --- | --- | --- | --- |
| 1 | 卷线器 | `2/2 → 1/2 → 0/2`，新局重置为 `2/2` | 单调递减，**推断为本局容错次数**（撞河豚扣 1，扣光后下一次撞击即断线结束） |
| 2 | 鱼钩 | `0/10 → 3/10 → 8/10 → 10/10`，且**增长集中在上浮阶段** | 本局已捕获数，满 10 结束本局。与引导文案「回收过程尽量捕获珍稀鱼类」完全吻合 |
| 3 | 鱼线 | `25 → 44 → 62 → 81 → 98 → 91 → 72 → 6 → 3` | 当前放线深度（米），下潜增、回收减。结算页显示「下潜深度：100米」，故上限即最大深度 |

## 引导文案原文（逐字）

1. 「鱼钩下潜时长按屏幕可左右移动，下潜至极致前不要碰到鱼。」
2. 「触碰鱼头可将其捕获，然后鱼钩将开始向上回收。」
3. 「鱼钩向上回收过程，尽量捕获珍稀鱼类确保收益最大化。」

这三句话就是玩法的地基：**下潜要躲鱼，上浮要撞鱼**。同一批鱼在同一次下潜中先是要避开的障碍、后是收益来源，天然形成风险与贪心的取舍。

## 钩子状态灯

钩顶小灯出现 **绿 → 黄 → 红** 三档，红色集中出现在钩上已挂多条鱼的回收段。判定为**线体张力指示**：负载越高灯越红，满则断线。

## 观测到的鱼种与角色

| 鱼 | 外观 | 角色 |
| --- | --- | --- |
| 河豚 | 圆胖带刺，体积最大，数量最多 | **全程障碍**，任何阶段都不能碰 |
| 黑白条纹小鱼 | 中型，成群 | 普通鱼，基础收益 |
| 红色小鱼 | 细长，游速快 | 中级鱼 |
| 极小杂鱼 | 成团出现 | 低价值填充，制造密度感 |
| 金色带状鱼 | 长条飘动，稀有 | 高价值，出现在深层 |
| 黄色方块鱼 | 方正 | 稀有鱼 |

## 结算面板「本次收获」字段

- 标题 `本次收获`，副标题 `下潜深度：100米`
- 鱼卡片网格（3 列）：稀有度星标 + 鱼图 + 两种货币数值（金币 / 贝壳）+ 橙色 `xN` 捕获数量
- 底部汇总两条货币栏：金币 100、贝壳 100
- 提示文案：`本次为体验关卡，不会获得奖励和图鉴`
- 按钮：`退出` / `继续体验`

说明游戏在单局之外还有**双货币 + 图鉴**的 meta 层，但录屏演示的是体验关，未实装。

# 三、玩法规则定稿

## 3.1 操作模型

| 输入 | 行为 |
| --- | --- |
| 按下并持续按住 | 鱼钩以 `DescendSpeed` 匀速下潜 |
| 按住期间横向拖动 | 鱼钩在井道内左右平移，速度受 `LateralSpeed` 限制，带轻微惯性 |
| 到达最大深度 / 首次捕获成功 | 自动切换为回收，无需玩家操作 |
| 松开（未下潜状态） | 无效果 |

鼠标与触摸走同一套：`Input.GetMouseButton(0)` 在 Android 上等价于单指按下，因此不需要两套逻辑。

## 3.2 阶段状态机

```text
Idle ──按下──► Descending ──触碰到鱼头──► Reeling
                    │                        │
                    │到达最大深度             ├─捕获成功─► Reeling(负载增加)
                    └────────────────────────┤
                                             ├─碰到河豚─► Tangled ──► Reeling / 断线
                                             └─回到水面─► Landed ──► 结算判定
结算判定 ──未达成结束条件──► Idle（下一轮）
         └─达成─────────► SessionEnd
```

## 3.3 判定规则

- **下潜阶段**：钩头碰到任何鱼 → 视为失误，扣 1 卷线器，鱼被惊散并向两侧逃逸
- **回收阶段**：钩头碰到鱼的**头部碰撞体** → 捕获成功，鱼挂上钩，负载与张力上升
- **河豚**：任何阶段碰到即判定受罚；它是体积最大的障碍，逼迫玩家规划穿行路线
- **张力**：每挂一条鱼按体型增加张力，满值则断线，本局立即结束且**只结算已带回水面的鱼**
- **半路脱钩**：回收途中张力满或撞河豚，钩上已捕获的鱼有概率脱落（体现"贪心代价"）

## 3.4 结束条件（任一满足）

1. 本局捕获数达到 `TargetCatchCount`
2. 卷线器归零后再次受罚
3. 张力断线
4. 到达最大深度并完成回收（深度用尽）

## 3.5 收益公式

```text
单条收益 = BaseValue(rarity) × DepthBonus(捕获时深度) × RarityMultiplier × ComboMultiplier
ComboMultiplier = 1 + 同一次回收内已捕获数 × ComboStep
```

DepthBonus 让"潜得更深 + 带得更多"同时成立才有高收益，直接对应引导第 3 句的收益最大化诉求。

# 四、MVC 架构落地

## 4.1 复用现有框架

工程内 QTower 框架已具备 MVC 全套骨架，本玩法**不新造框架**，只做业务填充：

| 框架能力 | 用途 |
| --- | --- |
| `UIManager` + `UIData` + `UIBase` | HUD / 引导 / 结算 / 倒计时四个面板 |
| `BaseController` + `ControllerManager` | `FishingController` 注册进 `ControllerType.Game` |
| `EventManager` + `EventDefines` | 阶段切换、捕获、受罚、结算等跨模块事件 |
| `ResManager`（Addressables + 对象池） | 鱼预制体实例化与池化 |
| `SoundManager` | BGM、下潜/捕获/断线音效 |
| `TimeManager` / `DurationTimer` | 倒计时、张力衰减、飘字节流 |
| `GameApp` 组合根 | 新增 `FishingSessionModel` 等模块的装配点 |

## 4.2 分层与目录

```text
Assets/Scripts/
├─ Game/                      已有：GameScene / GameApp / GameController
├─ Module/Fishing/            玩法模块（Model + 系统，不依赖 UI）
│  ├─ Model/                  FishingSessionModel, CatchRecord, HookState, TensionModel
│  ├─ Config/                 FishingLevelConfigSO, FishDataSO, HookConfigSO
│  ├─ Service/                FishSpawnService, FishAiService, RewardService
│  └─ Data/                   FishBreedTable(加权表), SpatialBucketGrid(空间分桶)
├─ UI/                        业务界面层（当前为空，正好落位）
│  ├─ UIFishingHUD/           UIFishingHUD + UIHudCounterItem
│  ├─ UIResultPanel/          UIResultPanel + UIResultFishItem
│  ├─ UITutorialPanel/        UITutorialPanel
│  └─ UICountdownPanel/       UICountdownPanel
└─ Framework/QTower/          不动
```

场景内的表现对象（钩子、鱼、鱼线、水体特效）不属于 MVC 三层的任何一方，归入 `Assets/Scripts/View/`（表现层 MonoBehaviour），由 Controller 通过事件驱动，自身不持有 Model 引用。

## 4.3 职责边界

- **Model**：纯 C# 类与 SO，不继承 MonoBehaviour，可脱离 Unity 单测
- **View**：只读 Model 的公开属性 + 订阅事件刷新，不写业务判定
- **Controller**：唯一可以修改 Model 的地方；输入意图 → 状态迁移 → 事件广播
- 跨模块通信一律走 `EventManager`，禁止 View 直接 Find Controller

## 4.4 事件定义（追加进 `EventDefines`）

| 事件名 | 携带数据 | 发布方 | 订阅方 |
| --- | --- | --- | --- |
| `FishingPhaseChanged` | `HookPhase` | HookController | HUD、水体表现 |
| `FishingFishCaptured` | `FishCaptureInfo` | FishingController | HUD 计数、结算数据、飘字 |
| `FishingPenaltyApplied` | `PenaltyType` | FishingController | HUD 卷线器、震屏 |
| `FishingTensionChanged` | `float 0-1` | TensionModel | 钩子状态灯、鱼线材质 |
| `FishingSessionCountdown` | `int` | FishingController | 倒计时面板 |
| `FishingSessionEnded` | `FishingSessionResult` | FishingController | 结算面板 |

# 五、关键数据结构

| 结构 | 选型 | 为什么这么选 |
| --- | --- | --- |
| 鱼种配置 | `FishDataSO`（ScriptableObject） | 数据驱动，新增鱼零改代码，满足题目"数据结构"考点 |
| 关卡配置 | `FishingLevelConfigSO` | 最大深度、目标捕获数、卷线器数、鱼群密度曲线全部外置 |
| 鱼群生成表 | 前缀和 + 二分查找的**加权随机表** | 按深度带抽鱼种，O(log n) 采样，比逐个累加Roll更适合密度随深度变化的需求 |
| 鱼群空间管理 | **均匀网格分桶**（一维数组存桶，桶内 List） | 钩子碰撞检测只查半径覆盖的 3x3 桶，避免每帧全量遍历；同时是"数据结构应用"的直接体现 |
| 钩上负载 | `Queue<CatchRecord>` + 累计张力 | 脱钩按先进先出，符合视觉表现 |
| 鱼行为 | `IFishBehavior` 策略接口 + 每鱼种一个实现 | 巡游 / 群游 / 惊散 / 逃逸 可组合替换 |
| 钩子阶段 | 显式状态机（`IHookState` + 字典索引） | 不用 enum + switch 堆叠，状态迁移可单测 |
| 结算聚合 | `Dictionary<FishId, CatchSummary>` | 结算卡片按鱼种合并计数与收益 |
| 飘字节流 | 环形缓冲（固定容量数组 + 头尾指针） | 限制同时存在的 TMP 实例数量，避免 GC 峰值 |

# 六、设计模式清单（对齐题目第 1 条）

| 模式 | 落地位置 | 解决的问题 |
| --- | --- | --- |
| MVC | QTower 全量复用 | 表现与规则解耦 |
| 状态模式 | `HookStateMachine` + `IHookState` | 下潜/回收/缠绕/落地迁移清晰 |
| 策略模式 | `IFishBehavior` | 鱼种行为差异不靠 if 分支 |
| 观察者模式 | `EventManager` | Controller 与 UI/特效零耦合 |
| 模板方法 | `UIBase.OnInit/OnOpen/OnClose/SubscribeViewEvents`、`BaseController.RegisterModuleEvent` | 生命周期统一，事件自动回收 |
| 组合模式 | `UIItemBase` + 结算卡片列表 | 面板由可复用子项拼装 |
| 工厂模式 | `FishFactory`（读 `FishDataSO` 产出实例） | 生成逻辑与资源加载解耦 |
| 对象池 | `ResManager.InstantiateFromPool / ReleaseToPool` | 鱼群高频生灭，杜绝 Instantiate/Destroy 抖动 |
| 单例 | `Singleton<T>`（`GameApp`） | 组合根唯一入口 |
| 外观模式 | `TimeManager`、`ResManager`、`SoundManager` | 屏蔽底层调度细节 |
| 数据驱动 | 全部 SO 配置 | 符合"禁止硬编码默认兜底"的项目规范 |

每个模式在代码注释里标注一句"为什么这里用它"，这是题目"考虑设计模式的应用"最直接的得分方式。

# 七、表现与手感（加分项，按性价比排序）

1. **鱼线**：`LineRenderer` + 每帧抖动曲线，负载越大抖动越明显；断线时线段回弹
2. **张力灯**：钩顶光点 `绿→黄→红` 材质插值，红色时呼吸闪烁
3. **水体分层**：深度越深颜色越暗 + 雾效插值，配合井道冰壁强化纵深
4. **捕获反馈**：命中瞬间 60ms 顿帧 + 小幅度屏幕震动 + 气泡粒子 + 音效
5. **结算飘字**：`+10` 从鱼的位置飞向货币栏，带缩放过冲
6. **鱼群摆尾**：顶点着色器正弦摆动（无需骨骼动画，成本低）
7. **断线慢镜头**：0.3 倍速 0.6 秒，强化挫败与戏剧性
8. **开局倒计时**：数字缩放入场，与录屏一致
9. **焦散与光柱**：一层滚动贴图，几乎零成本
10. **水面线**：正弦波纹 + 钩子出水时一圈涟漪

# 九、技术风险与决策

| 风险 | 说明 | 决策 |
| --- | --- | --- |
| 竖屏参考分辨率 | 现有 `UIRoot` 的 `CanvasScaler` 参考分辨率被设为 1920x1080（横屏） | 改为 **1080x1920**，Match 保持 0.5；M0 第一件事 |
| 输入系统 | 工程未装 `com.unity.inputsystem`，走旧 Input Manager | 用 `Input.GetMouseButton`/`GetAxisRaw`，Android 单指等价；封装 `IInputProvider` 便于日后替换 |
| Addressables 与 APK | 打包需要 Build Content，出包链路比 Resources 长 | 保留 Addressables（框架已依赖），M5 前先单独验证一次 Android 构建 |
| 渲染管线 | 工程为 URP 14.0.11，自定义 shader 需走 URP 版本 | 摆尾与焦散用 URP Compatible 的 Shader Graph 或手写 HLSL |
| 2D 还是 3D | 录屏是 3D 低模 + 竖屏窄视角 | 用 **3D 场景 + 正交相机**，鱼用低模 3D，兼顾还原与成本 |
| 美术工作量 | 题目允许简易资源，表现分主要靠光影与粒子 | 只做必需槽位清单，不铺场景美术 |
| 表现与性能 | 鱼数量大时 Update 峰值 | 鱼群统一由 `FishAiService` 批量驱动，不挂 MonoBehaviour.Update |
