# 04 - BUFF 体系定稿：能力线 × 装备藏品 × 布料

> 状态：口径已定，**数值全部为初值，待调**。
> 本文是三张表的唯一权威出处，代码与资产一律以此为准。
> 关联玩法：肉鸽背包路线 B（商店刷异形多格布料，玩家靠旋转与位移拼包）

---

## 〇、一句话口径

```text
布料（板块）  = 小额常驻 BUFF，放进背包就一直生效；一块布只有一个颜色，没有阵营
装备（藏品）  = 大头 BUFF，分一/二/三档，升档既变强又变占地
两条封顶      = 装备那份夹「能力线封顶」，布料那份夹「这块布自己每条 BUFF 的封顶」，互不干涉
```

五条定则：

1. **布料层不存在阵营**。一条布上面就是一个颜色，颜色只用来让玩家认出「这块布在往哪几条线上堆」，
   它既不生成资产、也不参与聚合、也不参与定价
2. 一块布可以挂**多条** BUFF（数组），常见～稀有一条，珍罕三条；
   复合布只在珍罕档出现，它是「一叠省格子的复合方案」，不是日常主力
3. 稀有度**同时驱动两件事**：抽中权重往下走、单价往上走，越稀有的布越贵也越难在货架上见到
4. 装备与布料**各夹各的封顶**：一块布铺满整张网也压不动装备，装备堆得再多也顶不掉布的封顶
5. **空白布必须进奖池且权重不低** —— 玩家必须能只买空间不买 BUFF，否则拼图取舍不成立

### 1.1 不进表的能力线（写死，别往回加）

| 字段 | 处置 | 理由 |
|---|---|---|
| `TensionMax` / `TensionRelief` | 接口字段**保留**，但**永久除名**出 BUFF 词表 | 主设计文档原话「张力上限字段保留但不参与判定」；本版鱼线不会断。张力目前是**只写不读**的半成品：`RarityRow.TensionLoad → FishDataSO.ResolveTensionLoad → FishCarryService 写入 CatchRecord.TensionLoad → 全工程零读取点`。接它等于先补完整个断线玩法 |
| `DetectRadius` | 同上，除名 | 显形裁剪未实现，现行接触裁决走 `HookRadius + 容差` |
| `StashCapacity` | 不进表 | 背包侧概念，`IFishingStats` 明令下潜层不得读背包概念；需要它时单开一个背包侧属性包 |
| `ComboStep` / `DepthBonusScale` | **永不进表** | 挂在 `FishingSessionConfigSO` 上的关卡难度参数，让玩家能买 = 让玩家能改肉鸽裁决的目标值 |

### 1.2 天然夹住、不需要额外封顶的一条

```text
MaxDepth = Mathf.Min(ShaftDepth, Stats.LineLength)
```
线长溢出会被井深夹住，所以 `LineLength` 的线封顶只是账面数字，不会穿地。

## 四、聚合规则（代码必须照这个算）

```text
1. 基准值全部来自 HookConfigSO，代码里不出现玩法常量
2. 布每格额度 × 异形占格数 = 该碎片贡献量（形状是 4 格就是 4 倍）
3. 按能力线分桶求和，正向线夹「基准 + 线封顶」，越小越好的线夹地板且不得为负
4. MaxCarryCount 是唯一取整的线：先按 float 累加，最后 FloorToInt 加到基准条数上
5. 两条封顶各夹各的，来源分账：
   ├─ 装备那份（CapOwner == null）合进线桶，夹 HookConfigSO.*BonusCap 的「线封顶」
   └─ 布料那份按 ClothBuffEntry 实例归组，夹这块布自己写的「布封顶」，桶内相加后并进线桶
   最终 bonus = Max(0, Min(装备合计, 线封顶)) + 布料合计（各自已夹完）
6. 负向线（DetachChance / TangledDuration）不设线封顶，装备与布的原始值透明相加，只夹配置地板
7. 封顶夹在「加成」上，不夹在最终值上；空白布零条目，自然不影响任何线
```

## 五、商店抽取与定价（全部参数在 SO 里）

```text
类别三选一     装备 : 带BUFF布 : 空白布 = 55 : 35 : 10      ShopConfigSO.*CategoryWeight
布内二选       空白布与带 BUFF 布各走一张表，表内按「稀有度抽中权重」加权
异形           抽中某块布后，在它的可刷异形数组里等概率挑一个
布料价         RoundToInt(单格基准价 × 占格数 × 稀有度价系数)，再乘 ±10% 浮动，下限 1
装备价         BackpackConfigSO.TierPriceList[档位]，同样吃 ±10% 浮动
空位           三类权重全部被清零或奖池为空时留空位，不硬塞
```

`ShopConfigSO.ClothCatalog` 是布料侧的唯一入口：布料不再有各自的清单资产，抽什么布、抽中多重、卖多贵全在总表里配。

## 六、数值待办

- 表①的「布每格 / 装备单件」是**同一条线的两个刻度**，调的时候必须一起看，不然布会反超装备
- `CoinBonus` 线封顶受接口硬约束 0.6，表里的 0.6 是天花板不是设计目标
- 抗造两条 ↓ 线的地板（0.05 / 0.1 秒）是「买不干净」的兜底，不是平衡值
- 稀有度权重 62/26/10/2 与价系数 1.0/1.6/2.4/4.0 都只做过分布验证，没做过「几回合买得起什么」的节奏验证
- 珍罕复合布的额度还没和「它省下的格子值多少钱」对齐，等扩容与格子经济一起定
- 装备三档数值与布封顶之间还缺一张回合节奏表，等玩法实机手感回来再补
