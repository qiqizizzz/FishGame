# 一、定位与主循环

一句话：**用背包 build 决定你能钓多深、能带回几条；用下潜验证这个 build。**

参考原型是《背包战斗》的网格背包 + 商店 + 合成，但把它的"自动战斗"换成**实时钓鱼**。这个替换是本设计的立身之本，见 2.2。

```text
  ┌──────────────────────────────────────────────────────┐
  │  下潜（唯一的实时技巧环节）                            │
  │     LineLength  = 能到多深（硬上限，不是倒计时）        │
  │     TensionMax  = 能拖多大的鱼（断了丢一半）            │
  │     CarryCapacity = 能带回几条（容量点数，见 2.2）      │
  └───────────────────────┬──────────────────────────────┘
                          ↓
                  出水结算：渔获 → 卖 → 金币 / 贝壳
                          ↓
              背包整备：钓竿（主武器）+ 藏品（BUFF）
                    网格 · 可旋转 · 3 同合成升品质
                          ↓
              商店（每潜 1 次）→ 三选一（每 3 潜 1 次）
                          ↓
              达成目标 → 解锁下一座岛（新鱼 + 新商品进奖池）
                          └──────────────→ 回到下潜
```

# 二、两条已定的方向性决策

## 2.1 全程竖屏（1080x1920）

| 依据 | 说明 |
| --- | --- |
| **深度分辨率翻倍（决定性）** | 同一套正交相机下，横屏把 100 m 摊在 1080 px 上 = **10.8 px/m**；竖屏摊在 1920 px 上 = **19.2 px/m**。玩法核心是垂直纵深，横屏等于把最重要的信息轴压缩一半 |
| 横向空间对钓鱼无收益 | 玩家不需要左右看，只需要看"下面还有什么" |
| 面试官预期锚点 | 题目录屏是 632x1264 竖屏 |
| 厂商取向 | 点点互动主做手游，竖屏是休闲市场默认 |
| 网格背包在竖屏放得下 | 1080 宽做 5 列 = **每格 216 px**，比同类竖屏网格背包（《咸鱼之王》《疯狂骑士团》）都宽松，图标 + 角标数字绰绰有余 |

**禁止混用朝向**（钓鱼竖屏 / 背包横屏）。转屏会直接打断手感连贯性，更要紧的是会逼出两套 `CanvasScaler` 与两套适配逻辑，污染整个 UI 架构——这恰好是题目第 1 条要看的东西。

参考图那种"左背包右商店"是横屏专属排版，竖屏改为上下分栏，见第四章。

## 2.2 渔获不占背包格，改用容量点数

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| 渔获进背包网格 | **放弃** | 会制造**第二个空间解谜**。下潜时的紧张感本该是"这条鱼张力快断了，我赌不赌"，一旦渔获要占格子，紧张感就退化成"我格子还够不够"。两个空间决策互相稀释 |
| 容量点数 | **采用** | 保留"带回哪几条"的真决策，零空间管理成本。且天然承接"增加钓竿可携带数量"这条升级线 |

**容量点数表**（按 02 的实测体长分档，规则外置到 `FishDataSO.CarryCost`，允许逐鱼微调）：

| 体长 | 容量 | 对应鱼（02 编号） |
| --- | --- | --- |
| < 0.30 m | 1 | SuperdwarfFish(A1) / Clownfish(A3) / Goldfish(A4) |
| 0.30–0.60 m | 2 | Angelfish(A7) / YellowBoxfish(A6) |
| 0.60–1.00 m | 3 | Anglerfish(A24) / Bass(A13) |
| 1.00–1.80 m | 5 | Oarfish(A18) |
| > 1.80 m | 8 | Tuna(A23) |
| 障碍 | 不占 | Pufferfish —— 碰即受罚，不参与携带结算 |

初始 `CarryCapacity = 4`。含义：开局能带 4 条杂鱼，或 1 条鲈鱼 + 1 条杂鱼。想带金枪鱼（8）必须先扩容——**这就是 build 与战利品之间的耦合点**。

# 三、`IFishingStats`：整个扩展层的唯一接口

这是本篇最重要的一条架构约束。**下潜层不允许读任何背包概念**，只读一个由背包聚合出来的只读属性包。

```text
背包物品 ──(Apply)──> IFishingStats ──(消费)──> 下潜 / 张力 / 生成 / 结算
```

| 字段 | 类型 | 初始值 | 谁能改 | 玩法含义 |
| --- | --- | --- | --- | --- |
| `LineLength` | float (m) | 25 | 钓竿、线轮类藏品 | **能到多深**。硬上限，钩子顶到线头而下方仍有鱼 = 核心挫败感来源 |
| `CarryCapacity` | int | 4 | 钓竿、鱼篓类藏品 | 能带回几条（见 2.2） |
| `ReelSpeed` | float (m/s) | 3.0 | 卷线器类藏品 | 收线速度，影响"大鱼能不能拖到水面" |
| `TensionMax` | float | 100 | 钓竿、握把类藏品 | 张力上限，超过即断线 |
| `TensionRelief` | float (0–1) | 0 | 缓震类藏品 | 断线前的缓冲窗口比例 |
| `HookCount` | int | 1 | 特殊钓竿 | 一次能挂几条鱼（后期扩展，P0 恒为 1） |
| `LurePull` | float | 1.0 | 饵料消耗品 | 稀有度权重放大系数，作用于加权随机表 |
| `DetectRadius` | float | 0.8 | 探照灯类藏品 | 鱼显形半径，深水区关键 |
| `CoinBonus` | float (0–1) | 0 | 藏品 | 卖鱼金币加成，**上限锁 0.6** |

**聚合方式**：背包内物品按「钓竿优先、藏品按格坐标行主序」依次 `Apply(stats)`，产出不可变结构体，出水与整备时各重算一次。**不做增量缓存**——物品数量上限 35，全量重算是纳秒级，换来零状态同步 bug。

# 四、竖屏三栏布局（尺寸定稿）

基准 1080x1920，`CanvasScaler` = ScaleWithScreenSize / 1080x1920 / Match 0.5。

| 区域 | 屏幕矩形 (y 自顶向下) | 内容 | 备注 |
| --- | --- | --- | --- |
| 状态条 | 0 – 120 | 金币 / 贝壳 / 当前潜次 / 目标进度 / 图鉴入口 | 常驻，高 120 |
| 背包网格 | 140 – 1220 | 5 列 x 5 行起步，可扩至 5x7 | 每格 **216x216**；5 列宽 = 1080 正好铺满 |
| 商店 / 三选一 | 1240 – 1740 | 一排 4 个商品 + 价格角标 + 刷新按钮 | 三选一时整块替换为竖排 3 张卡 |
| 行动按钮 | 1760 – 1920 | 「下潜」主按钮（居中，直径 140） | 全局唯一 CTA，避免误触 |

背包区高 1080 / 5 行 = 216，与列宽一致，**格子是正方形**。扩到 7 行时把商店区压到 1440–1740（300 高，商品改为横向滚动），不动状态条。

# 五、背包网格系统（题目第 1 条的主战场）

| 结构 | 选型 | 为什么这么选 |
| --- | --- | --- |
| 网格占用 | **`ulong` 位图**（5x7 = 35 格，落在 64 位内） | 放置校验 = 一次 `位与`；旋转 = 查预计算掩码表。比 `List<RectInt>` + 逐个 AABB 相交干净一个数量级，且是"数据结构应用"最直接的展示位 |
| 物品形状 | 相对格坐标数组 `Vector2Int[]`（如 L 形、1x2、2x2、十字） | 不用矩形近似，能表达《背包战斗》那种异形藏品 |
| 旋转 | 形状点集 `(x,y)→(y,-x)` 归一化后**预计算 4 个朝向**缓存 | 运行时零计算；位图侧用同一张朝向表做 `>>` 位移 |
| 落位校验 | `mask & occupied == 0 && (mask & gridMask) == mask` | 一行表达式同时完成越界与重叠检测 |
| 物品定义 | `ItemDataSO`：品质 / 形状 / 朝向缓存 / `Apply(IFishingStats)` / 售价 / 合成 key | 数据驱动，新增物品零改代码 |
| 合成规则 | `SynthesisRuleTableSO`（输入品质 + 数量 + 形状 → 输出），**规则表驱动** | 禁止 if-else 硬编码品质链；策划可改 |
| 快速合成 | 全表扫描 `Dictionary<synthKey, List<slot>>`，数量 ≥ 3 即高亮 | 参考图左上「快捷合成」按钮 |
| 商店库存 | 岛屿解锁池 + 权重表 + **保底计数器** | 连续 N 潜不出高品质则强制插入，防极端脸黑 |
| 三选一 | 条件过滤器链（`ICardFilter` 串接）+ 加权抽取 | 责任链 + 策略，两个模式同一处落地 |

# 六、品质与合成

**品质链白 → 蓝 → 紫 → 金直接复用已落地资产**，零新增成本：

| 品质 | 复用对象 | 颜色 |
| --- | --- | --- |
| 白 | `Mat_Fish_Common` / `T_Fish_Mod_Common` | `#C9CDD2` |
| 蓝 | `Mat_Fish_Rare` / `T_Fish_Mod_Rare` | `#3E7BFA` |
| 紫 | `Mat_Fish_Epic` / `T_Fish_Mod_Epic` | `#8B5CF6` |
| 金 | `Mat_Fish_Legendary` / `T_Fish_Mod_Legendary` | `#F5B93B` |

即 `RarityTableSO` 同时服务三处：鱼身配色、结算 UI、**背包物品品质边框与角标**。颜色与数值同源，符合 01 第 3.6 节"杜绝硬编码散落"。

合成规则（待数值细化，先定形）：

- **3 个同品质 + 同 synthKey 的物品 → 1 个高一品质**，形状**可变**（默认继承输入中最大者）
- 跨类不合成（钓竿线与藏品线各自成链）
- 金品质为顶，不再合成
- `Uncommon` 档（`#4CAF7D` 绿）在本篇**不启用**，保留给"特殊功能藏品"作区分色，避免与四档链混淆

> 注意：01 第 3.6 节的五档稀有度描述的是**鱼的价值档位**，本篇四档描述的是**物品品质档位**，两套语义不同但共用同一张 `RarityTableSO` 的配色。实现时用两个独立枚举（`FishRarity` / `ItemQuality`），靠映射表关联，**不要复用同一个枚举**。

# 七、岛屿分层与永久解锁

这一章是肉鸽平衡的生死线，必须守住一条铁律。

| 层 | 内容 | 是否跨局保留 | 例子 |
| --- | --- | --- | --- |
| **run 内推进** | 当前潜到第几座岛、背包里的物品、金币 | **否，每局重置** | 第 3 潜达标 → 本局解锁第二座岛 |
| **永久解锁** | **内容池**：哪些鱼种、哪些物品会进入随机奖池 | 是 | 首次钓到皇带鱼 → 之后所有局的奖池里都可能出现它 |
| **永久成长** | 仅图鉴带来的**小额**全局加成 | 是 | 图鉴完成度每 20% 给 +2% 金币，**总上限 +10%** |

> **铁律：永久解锁只能解锁内容，不能解锁强度。**
> 卖鱼的钱只能在**本局内**花。若允许跨局买永久数值，第 20 局会无聊到爆，肉鸽的重玩动机当场失效。

用户提出的"一开始只能钓小鱼 → 卖鱼 → 解锁新岛屿（新鱼 + 商店种类增加）"天然落在**内容池**这一侧，方向正确。落地时拆成两跳：

1. **本局内**：达标即进入下一座岛（临时，下局重来）
2. **跨局**：该岛被"通关过"则其鱼种与商品**进入解锁池**，之后随机局的商店可能刷出来

岛屿与深度带对齐（复用 01 第 3.6 节的深度带定义）：

| 岛 | 深度范围 | 主要稀有度 | 解锁条件（待细化） |
| --- | --- | --- | --- |
| 岛 1 浅滩 | 0–25 m | Common / Uncommon | 初始 |
| 岛 2 礁坡 | 0–50 m | + Rare | 单局渔获价值 ≥ N1 |
| 岛 3 断崖 | 0–80 m | + Epic | 单局渔获价值 ≥ N2 |
| 岛 4 深渊 | 0–100 m+ | + Legendary | 单局渔获价值 ≥ N3 |

解锁门槛用"渔获价值"而非"分数"，目标是钓鱼语义，玩家不必理解第二套数值体系。

**关卡形态定稿：教学关 + 1 个有目标值的正式关。不做无尽关。**

理由：无尽关没有"完成"判定，试玩 5 分钟体验不到闭环；而"有目标值 → 达成 → 结算"能完整展示 目标系统 / 状态机 / 事件流，这正是题目第 1 条最好的展示位。无尽模式作为 P3 之后的可选扩展。

# 八、藏品叠加约束

背包英雄类产品最常见的死法是"藏品效果互相不知道能不能叠加、谁先算、能不能改规则"。现在就定死：

> **规则：所有藏品只能修改 `IFishingStats` 的字段，不得引入任何新机制。**

| 允许的藏品效果 | 禁止的藏品效果 |
| --- | --- |
| `LineLength += 8` | "每 3 潜送一条鱼" |
| `TensionMax *= 1.25` | "有 20% 概率免疫断线" |
| `LurePull += 0.3` | "解锁双钩模式" |
| `CoinBonus += 0.1` | "把白品质鱼升级为蓝品质" |

想加新机制的东西，走**钓竿本体**（它有配件槽）或**饵料**（它是消耗品，天然可承载一次性规则）。藏品只负责数值。

配套约束：

- 同类字段**加法优先于乘法**；必须用乘法时，字段名以 `Mult` 结尾，聚合阶段统一先加后乘
- 每个字段声明 `Min` / `Max` 硬边界（如 `CoinBonus` 锁 0.6），聚合后一次性 clamp，防止叠加爆炸
- 藏品不写"触发时机"，任何需要监听事件的物品都不是藏品，归入饵料或钓竿配件

# 九、分阶段落地

每阶段结束都是一个**可提交、可玩、可讲的完整物**。这是为了对冲一个真实风险：题目第 1 条考的是工程能力，半成品肉鸽的得分大概率低于完成度高、结构干净的钓鱼游戏。

| 阶段 | 内容 | 可交付判定 | 对应题目考点 |
| --- | --- | --- | --- |
| **P0** | 核心钓鱼闭环（01 的 M0–M2）+ `IFishingStats` **以默认值实现** | 单局能下潜、能断线、能出水结算 | 状态模式、策略、对象池、MVC |
| **P1** | 背包网格 + 旋转 + 合成 + `IFishingStats` 由背包驱动 | 摆放/旋转/合成可玩，改背包后下潜参数**真的变了** | **数据结构主战场**：位图、形状表、规则表 |
| **P2** | 商店 + 每 3 潜三选一 + 金币经济 | 完整 3 潜循环，build 有成长曲线 | 权重采样、责任链、策略、数据驱动 |
| **P3** | 图鉴 + 永久解锁池 + 存档 + 岛屿分层 | 跨一局验证"内容池扩大、强度不扩大" | 序列化、版本兼容、存档迁移 |

**P0 就必须把 `IFishingStats` 立起来**（哪怕所有字段都是常量）。否则下潜层会散落一堆硬编码深度/容量常量，P1 接背包时全要返工。

# 十、待细化

1. 各岛渔获价值门槛 N1–N3，与鱼单价、每潜期望收益联立求解
2. 断线惩罚强度：丢全部渔获 / 丢一半 / 只丢当前这条——决定风险曲线陡度
3. 钓竿配件槽数量与形态（是否也占背包格）
4. 饵料是占背包格还是独立快捷栏（占格会与藏品抢空间，不占则削弱其决策权重）
5. 三选一卡牌池规模与稀有度分布（建议首批 12 张跑通，再扩到 30）
6. 贝壳（第二货币）的用途：01 结算面板已有该字段，本篇尚未给它定位
7. 教学关教到什么程度：只教下潜收线，还是把背包合成也教完
